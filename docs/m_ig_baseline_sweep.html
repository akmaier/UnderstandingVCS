Integrated Gradients

Sundararajan et al. 2017

← back to the method catalogue

What it does?

Integrated Gradients attributes the output to inputs by integrating the gradient along a straight path from a chosen baseline to the actual input. Instead of the gradient at a single point, which can be misleading if the output has saturated, it accumulates the gradient over the whole path. This gives the method its completeness property: the attributions add up exactly to the difference between the output at the input and the output at the baseline. The attribution depends on which baseline is chosen, an all-black image, a mean image, and so on, so we sweep several baselines and report the behaviour. We apply it to the VCS by integrating each cause's gradient from a baseline state to the live state and correlating with the true causal map. On smooth content outputs it behaves like a stronger saliency and concentrates mass on the true causal byte. On a sprite's position the completeness property does not save it: the position is a discrete strobe-timed step, so the naive gradient along the whole path is zero, and the integral of zero is zero. The baseline choice moves the magnitude of the attribution but not its correlation with the truth. Integrated Gradients is an axiomatic, much-cited method, which makes it an important reference point for what completeness can and cannot fix on discrete outputs.

The idea in plain words

Vanilla saliency has a blind spot called saturation. Picture a network that is already 99.9 % sure the photo shows a dog. Making the dog's ear a bit brighter cannot raise the score much more, so the gradient there is almost zero. Yet the ear is a big reason the score is high. The gradient only sees the flat top of the curve, not the climb that got there.

Integrated Gradients (IG) looks at the whole climb. It chooses a baseline: an input that means “nothing”, such as a black image. It walks in a straight line from the baseline to the real input, adds up the gradients along the way, and multiplies by how far each input moved. The payoff is completeness: the attributions add up exactly to the output at the input minus the output at the baseline. The price is that the answer depends on which baseline you pick. So our runner tries four baselines and reports how much the result moves.

How it works on a neural network

With \(y = f(x)\) and a baseline \(x^0\), IG assigns input \(i\)

\[ \mathrm{IG}_i(x; x^0) \;=\; (x_i - x^0_i)\int_0^1 \frac{\partial f}{\partial x_i}\big(x^0 + \alpha\,(x - x^0)\big)\,d\alpha . \]

The integral is a line integral of the gradient along the straight path. By the gradient theorem (the fundamental theorem of calculus for paths) the pieces sum to the total change: \(\sum_i \mathrm{IG}_i = f(x) - f(x^0)\). In practice the integral is a Riemann sum over \(K\) points, e.g. midpoints \(\alpha_k = (k - \tfrac12)/K\).

Toy example (2 inputs). \(f(x_1, x_2) = x_1 x_2\) at \(x = (2, 3)\), baseline \(x^0 = (0, 0)\). On the path \(x(\alpha) = (2\alpha, 3\alpha)\) the gradient is \((3\alpha, 2\alpha)\). Then

\[ \mathrm{IG}_1 = 2\int_0^1 3\alpha\,d\alpha = 3, \qquad \mathrm{IG}_2 = 3\int_0^1 2\alpha\,d\alpha = 3, \qquad 3 + 3 = 6 = f(x) - f(x^0). \]

Completeness holds. Compare: saliency gives \((3, 2)\), and Grad×Input gives \((6, 6)\), which sums to 12, twice the real change.

Saturation. Let \(f(x) = \min(1, x)\) at \(x = 2\). The gradient is 0, so saliency says “irrelevant”. IG from \(x^0 = 0\) integrates slope 1 over the first half of the path: \(\mathrm{IG} = 2 \cdot \tfrac12 = 1 = f(2) - f(0)\). IG sees the climb.

Baseline dependence. Back to \(x_1 x_2\), now with baseline \(x^0 = (2, 0)\). \(x_1\) does not move, so \(\mathrm{IG}_1 = 0\), and \(\mathrm{IG}_2 = 3 \cdot 2 = 6\). Same model, same input: all the credit moved to \(x_2\). The baseline defines the question being answered.

Recipe

  1. Choose a baseline \(x^0\) (zeros, a mean input, noise, or a real reference input).
  2. Pick \(K\) points on the straight path, \(x^0 + \alpha_k (x - x^0)\) with \(\alpha_k = (k - \tfrac12)/K\).
  3. At each point run one backward pass to get \(\partial y/\partial x_i\).
  4. Average the \(K\) gradients and multiply element-wise by \((x - x^0)\).
  5. Check completeness: \(|\sum_i \mathrm{IG}_i - (y(x) - y(x^0))|\) should be small; if not, increase \(K\).
  6. Repeat for several baselines and compare: the spread is part of the answer.

How we apply it to the VCS

The runner integrates the gradient over the RAM vector with \(K = 64\) Riemann midpoints, for each of four baselines, and scores each IG map against the oracle. It also records each baseline's completeness error. The headline number uses the all-zeros baseline; the sweep sits beside it.

  • What about non-integer RAM? A point halfway along the path has bytes like 63.5. A real 6507 cannot run on that. The code never asks it to. At each path point it evaluates only the differentiable read of the output (soft_ram_peek or the bilinear sampler), which is defined for any real number. The machine itself only runs during the oracle and the deletion/insertion curves, always on integer pokes. As in vanilla saliency, the 15 frames between \(f^*\) and the readout are not differentiated.
  • Content output. The read is linear, so the gradient is the same one-hot vector \(e_s\) at every path point. IG reduces to \(\mathrm{IG}_s = x_s - x^0_s\) and 0 elsewhere. Completeness is exact for every baseline. Changing the baseline only changes the height of one spike, so the ranking of causes, and hence the correlation with the oracle, stays put. One exception: if the baseline happens to equal the byte's value, the spike vanishes. The sweep makes this baseline degeneracy visible.
  • Position output. The naive gradient is zero all along the path, and the integral of zero is zero, for every baseline. With the sampler on, completeness gives \(\mathrm{IG} = \text{sampler}(x) - \text{sampler}(x^0)\): the difference in the cell's occupancy between the sprite drawn at the baseline's column and at the real one. If the cell is empty at both ends, IG is zero even when the sprite passed through the cell on the way.
  • The four baselines. zeros is the classic “absent” input. mean_ram fills all 128 bytes with one number, the mean of the current RAM. random is one seeded uniform draw in 0–255. real_alt is the genuine RAM at frame \(f^*/2\) of the same seeded run. It is the only baseline that is itself a reachable game state.
  • Scoring is the shared contract: correlation and precision@3 against the oracle, deletion/insertion curves on the real ROM, and an oracle-vs-itself control.

Reading the result

The headline bars use the zeros baseline. On the content output you see one spike at the read byte, as in vanilla saliency. Its height is the byte's distance from the baseline. Across the baseline sweep the spike grows or shrinks, but the correlation with the oracle barely moves. It drops to nothing only when a baseline equals the byte. The completeness error is essentially zero throughout. On the position output, agreement with the oracle stays low for every baseline. Completeness is a bookkeeping guarantee about the total; it does not make IG notice the several causes the oracle finds over 15 frames.

Pitfalls

  • The baseline is a hidden choice. Different baselines answer different questions (“compared with what?”). A black baseline gives zero credit to black pixels; Sturmfels et al. show how much maps change with it.
  • Off-distribution path. Points along the straight line are blends that no real input looks like. On the VCS they are fractional RAM states the machine cannot run, so IG explains the differentiable read, not the machine's behaviour on them.
  • Completeness is not correctness. Attributions that sum to the right total can still credit the wrong inputs. On discrete outputs the total itself can be zero.
  • Riemann error. Too few steps break completeness on curved functions. Check the completeness error, as the runner does.
  • Integral of zero is zero. Where the gradient vanishes along the whole path (sprite timing, table look-ups), no baseline helps.

How it's scored

The score is the Pearson correlation of the Integrated-Gradients attribution with the oracle's exact causal map, reported raw, at the headline baseline, with the baseline swept to show the dependence. Faithfulness for this method is that correlation, graded always against the intervention oracle. On smooth content outputs it behaves like a stronger saliency and scores well, and sweeping the baseline moves the magnitude of the attribution but not its correlation with the truth, because the constant one-hot Jacobian keeps the mass on the same byte. The hard case is a sprite's position. The position is a discrete strobe-timed step, so the naive gradient along the whole integration path is zero, and the integral of zero is zero; completeness does not rescue it. The audit turns on the differentiable sampler to give the method a fair chance on position, but the restored gradient is faithful on only a minority of games, so the position score stays low. The audit box reports the all-regime faithfulness, which averages the strong content result and the weak position result across the scored games. This makes Integrated Gradients a key reference for what the completeness axiom can and cannot fix on discrete outputs.

The score is measured against the §1 intervention oracle — never against another interpretability method. F (faithful) is always vs the oracle; see the execution stack. How each of F / S / M is actually computed for this method (and whether it matches the paper) is in the box just below; the numbers are in the In the audit box under it.
