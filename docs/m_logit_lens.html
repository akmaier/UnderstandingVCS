Phase C · mechanistic interpretability

Logit / tuned lens

nostalgebraist 2020; Belrose et al. 2023

← back to the method catalogue

What it does?

The logit lens reads a system's intermediate state through its own output decoder. In a transformer it takes the hidden state at some middle layer and applies the final output projection to it, as if that intermediate state were the last layer, to see what the model would 'say' at that point. This reveals how the prediction forms across depth, and the tuned-lens variant learns a small correction so the readout is more faithful at each stage. It is a standard, cheap tool for tracing how information develops inside a network. We build the analogue on the VCS by reading an intermediate value through the machine's own decoding, and comparing the decoded value to the true intermediate value at that site. On this transparent machine the readout is exact: the state is linearly readable at the right site, so the lens reproduces the true intermediate value on every game. This is expected, because the VCS keeps its variables in plain, addressable memory rather than in a distorted distributed code. Readability, however, is only the positive control. The scored question is where the lens's readout weight sits: on the cells the oracle marks as truly causal, or on clocks and counters that merely co-vary with the value. Reading the right value at the right site confirms that the value is represented and readable, but it does not by itself explain how that value is computed or what role it plays.

The idea in plain words

A transformer language model is a stack of layers. Each layer reads a shared vector, the residual stream, and adds its contribution back to it. Only at the very end does an unembedding matrix turn that vector into one score per word in the vocabulary. Those scores are the logits; a softmax turns them into probabilities for the next word.

The logit lens asks a cheeky question: what if we applied that final unembedding to the residual stream halfway up the stack, as if the model stopped there? Because every layer writes into the same stream, this often gives sensible words. You can watch the prediction form layer by layer: vague at first, then sharpening into the final answer. The tuned lens improves on it. It learns a small linear correction for each layer, so that earlier layers, whose “language” drifts a little from the last layer's, are translated before decoding. Both are cheap, popular ways to trace how information develops through depth.

How it works on a neural network

Let \(h_\ell\) be the residual stream after layer \(\ell\), \(W_U\) the unembedding and \(\mathrm{LN}\) the final layer normalisation. Then

\[ \text{logits}_L = W_U\,\mathrm{LN}(h_L), \qquad \text{logit lens: } W_U\,\mathrm{LN}(h_\ell), \qquad \text{tuned lens: } W_U\,\mathrm{LN}(A_\ell h_\ell + b_\ell). \]

The tuned-lens translator \((A_\ell, b_\ell)\) is trained so its output distribution matches the model's final one (by minimising a KL divergence). No new information is created: the lens only reads what is already linearly there.

Toy example. A vocabulary of two words, “Paris” and “Rome”, and \(W_U = I\) (identity). The residual stream after layers 1, 2 and 3 is \((0.2, 0.1)\), \((1.5, 0.3)\) and \((3.0, 0.2)\). The softmax probability of “Paris” is \(1/(1+e^{-(z_1-z_2)})\): 0.52 after layer 1, 0.77 after layer 2, 0.94 after layer 3. The logit lens shows the answer “Paris” forming gradually. If layer 1 stored the answer in a rotated basis, the raw lens would read nonsense there, and a learned \(A_1\) would undo the rotation: that is the tuned lens.

Recipe

  1. Run the model and save the residual stream \(h_\ell\) at every layer.
  2. Logit lens: apply the final norm and unembedding to each \(h_\ell\) and read the decoded prediction.
  3. Tuned lens: for each layer, fit an affine map \(A_\ell h_\ell + b_\ell\) on training data so the decoded output matches the final output.
  4. Evaluate on held-out data: how well does each layer's readout match the final answer, and from which layer on?
  5. Check what the readout relies on: are its weights on components that actually drive the output?

From a neural network to the Atari

Layers \(\ell\)The frames of the 15-frame horizon after \(f^*\): step 0 (the checkpoint) to step 15.
Residual stream \(h_\ell\)The full 128-byte RAM at that step. RAM is the one state every frame reads and writes, like the residual stream.
Final logitThe value of a target variable's RAM cell at the end of the horizon (one per candidate cell; 8 for Pong).
Unembedding \(W_U\) (logit lens)The identity readout: read the target's own cell at step \(t\). There is no learned matrix on the VCS.
Tuned-lens translator \(A_\ell, b_\ell\)A ridge-regression readout from all 128 bytes at step \(t\) to the final value.
True intermediate value (unknown in an LLM)The actual byte at that step on the bit-exact run, plus the oracle's mask of which cells causally drive each final value.

How we apply it to the VCS

Our runner logit_lens.jl builds both lenses on the VCS and scores them against values we can measure directly.

  • A set of runs to fit on. A lens needs many examples. From the shared gameplay checkpoint at \(f^*\) we record 48 runs of 16 steps each: the clean run, a source run whose last prefix action is RIGHT, and 46 runs that each start with one candidate cell shifted by 17, 34, 64, 128 or 200. Every run is a genuine bit-exact replay of the ROM, so every row is a real machine state.
  • Logit lens. For each target variable and step \(t\), read its own cell. Against the true intermediate value this has fidelity (\(R^2\)) of exactly 1, because the readout is the cell. It is a positive control that the readout site is right, not a discovery. Against the final value it shows how early the cell already holds its end-of-horizon value.
  • Tuned lens. For each variable and step, fit a ridge regression (\(\lambda = 10^{-3}\)) from all 128 bytes to the final value on 70 % of the runs, and score \(R^2\) on the other 30 %. The earliest step with \(R^2 \ge 0.9\) is when the answer is “already there”.
  • Faithful or spurious? The oracle sets each candidate cell to its value + 17 at \(f^*\), replays, and marks which final values change. At the tuned lens's earliest decoding step we measure what share of its weight magnitude sits on those truly causal cells. A high share means the lens reads the mechanism. A low share means it found a correlate, for example a counter that happens to predict the answer.

Where we differ from the original. A transformer has one shared unembedding; on the VCS each variable lives in its own address, so the “unembedding” is just “look at that address”. Our layers are time steps, not stacked modules. And the training runs are mostly deliberate pokes, not a natural data distribution. Readout fidelity reaching the ceiling is therefore expected: the machine keeps its variables in plain, addressable memory. The more informative numbers are the tuned-lens curves and the faithful-weight share, which is the record's scored faithfulness.

Reading the result

The figure plots readout fidelity against the true intermediate value, step by step, and it sits at the ceiling on every game. Read that as a sanity check: the variable is stored at the site we read, in plain form. The richer story is in the per-step curves. The logit lens reaches the final value only once the cell stops changing. The tuned lens can sometimes predict it earlier by combining other bytes. Then check the faithful-weight share: an early prediction built on causal cells is the mechanism showing through; one built on non-causal cells is a correlation, the same present-versus-used trap as in probing.

Pitfalls

  • Readable is not explained. Reading the right value at the right place confirms it is represented. It says nothing about how it is computed or what role it plays later.
  • Representation drift. In a transformer, early layers may use a different basis than the last one, so the raw logit lens reads nonsense there. That is why Belrose et al. propose the tuned lens.
  • A tuned lens can learn too much. A flexible translator fit per layer can find correlates that the model never uses. Check which inputs carry its weight, as we do with the oracle mask.
  • Off-distribution fitting. Our training runs are mostly deliberate single-cell pokes. Readouts fit on them may not transfer to ordinary gameplay states.

How it's scored

The scored faithfulness is the faithful-weight fraction. For each game variable we fit a tuned lens (a per-step linear readout) and find the earliest step at which it decodes the variable's final value. At that step we measure what share of the lens's readout weight sits on cells the intervention oracle marks as truly causal for that variable, rather than on correlated clocks and counters. A high share means the lens reads the mechanism; a low share means it rides a correlate. Readout fidelity, the R-squared of the lens-decoded value against the true intermediate value, is kept as a positive control and is the quantity the example figure plots: on this transparent machine the state is linearly readable at the right site, so fidelity sits at the ceiling. The point of the faithful-weight score is that readability alone does not show use. A readout can decode a value early by combining cells that merely co-vary with it. There is no sprite-position hard-case here, because the method reads an internal value rather than a rendered position, and it does not rely on a gradient. The grading is always against the oracle; the audit box reports the measured triad.

The score is measured against the §1 intervention oracle — never against another interpretability method. F (faithful) is always vs the oracle; see the execution stack. How each of F / S / M is actually computed for this method (and whether it matches the paper) is in the box just below; the numbers are in the In the audit box under it.
