A8 · Whole-state recording

cf. Jonas & Kording 2017

← back to the method catalogue

What it does?

Whole-state recording is the simplest possible method: write down everything. At each step we record every bit of RAM and every register, the complete internal state over time. This is the raw material that every other method in the study works from. In neuroscience it is the dream of recording every neuron at once, and it is often treated as the thing that would finally let us understand the system. The intuition is that if we have the full state, we have hidden nothing, so we must have the explanation. We include it as a deliberate baseline to test that intuition. By construction the complete record is perfectly faithful and perfectly sufficient: it contains every cause, so nothing is missing, and it can predict any intervention because it holds the whole machine. The point of including it is to show what such a record still lacks. A dump of all 128 RAM cells is not an account of the computation. It names everything, so it names nothing in particular, and the true cause of any given output is a tiny handful of those cells. Completeness is not understanding, and this method makes that concrete.

The idea in plain words

Every method in this battery looks at part of the system: one unit, one pair, one pooled signal. The obvious objection is “then record everything”. Neuroscience has pursued that dream for decades. Large projects aim to record every neuron of a brain at once, and techniques such as calcium imaging already capture tens of thousands of cells. The hope behind it is that once nothing is hidden, understanding will follow.

A8 tests that hope on a machine where the dream is already true. The Atari's complete state is tiny, and we can copy all of it at every frame. Such a record is a perfect description: it misses nothing, and from it the machine can be rebuilt exactly. But is it an explanation? An explanation should also be small: it should point at the few things that matter for the output you asked about. A8 is the deliberate baseline that scores perfectly on completeness and at the floor on smallness. It makes the gap between having the data and understanding the system measurable.

How it works on a neural network

Neuroscience origin. Whole-brain or whole-population recording: the Brain Activity Map / BRAIN Initiative vision (Alivisatos et al. 2012) of measuring every spike of every neuron. Jonas & Kording had the complete state of their simulated chip at every step, with every transistor known, and showed that standard analyses of it still failed to reveal how the chip ran its programs.

Deep-learning analogue. Dumping every activation: caching all hidden states of every layer for an input, the way interpretability libraries “run with cache”. It is always the first step, never the explanation. To grade it, we use the study's three axes. With \(U^*\) the true minimal set of causes of an output and \(\hat U\) the set an explanation names:

\[ F = \frac{|U^*\cap \hat U|}{|U^*|}\ \text{(nothing causal left out)}, \qquad S = \text{does }\hat U\text{ reproduce the output?}, \qquad M = \frac{|U^*|}{|\hat U|} . \]

(The study defines F per method; for a set-valued explanation like this one it is the recall above.) A full dump names every unit, so \(\hat U\) is everything. It contains every cause (F = 1), it reproduces the output (S = 1), and M is as small as it can get.

Toy example. A network has 1000 hidden units. For one prediction, careful ablations show that only 3 units matter. The activation dump lists all 1000 numbers: F = 1, S = 1, and \(M = 3/1000 = 0.003\). A good explanation names those 3 units: F = 1, S = 1, M = 1. Same faithfulness, opposite usefulness. M is the axis that tells them apart.

Recipe

  1. Record the complete internal state at every time step (every unit, every register).
  2. Present the full record as the “explanation”: its named set \(\hat U\) is the whole state.
  3. Check faithfulness: does \(\hat U\) contain every true cause? (Trivially yes.)
  4. Check sufficiency: restore the recorded state and confirm it reproduces the output exactly.
  5. Find the true minimal cause set \(U^*\) by intervention and compute \(M=|U^*|/|\hat U|\).
  6. Run the control: the oracle's own minimal set must score F = S = M = 1.

How we apply it to the VCS

The runner A8_wholestate.jl is short, because the method is trivial. What it measures is not.

  • Recording. From the shared gameplay state (seeded random actions, checkpoint at frame \(f^*=90\), 15-frame horizon), record_whole_state steps the real ROM with env_step! for 150 frames, continuing with NOOP after the gameplay window. It stacks get_ram and the TIA register file into a \(T\times192\) tape. Per-byte range and variance are kept as the descriptive map.
  • Ground truth. oracle_causal_importance copies the checkpoint, writes each candidate byte to 0, base+17 and base+37, runs the 15-frame horizon and counts changed screen pixels. A byte with any effect is causal. These bytes form \(U^*\).
  • F and S. F is 1 by construction, because the dump contains every byte. verify_wholestate_sufficiency writes the recorded 128 RAM bytes into a fresh copy of the checkpoint and compares RAM and screen with the recording. As the code itself notes, this is an identity restore. It confirms the recorder is lossless; it is not a hard test.
  • M, the headline. \(M = |U^*|/128\). The runner also reports the over-recording factor \(128/|U^*|\): how many times larger the dump is than the true cause set.
  • Positive control. verify_minimal_sufficiency restores only the causal bytes (again over the same checkpoint) and checks the frame is still reproduced. The oracle's own set then scores M = 1, proving the harness rewards small explanations and that the dump's low M is a real measurement.

Honest caveats. \(U^*\) is searched only among the game's candidate bytes, with three poke values and one horizon. Bytes outside that list are never tested, so \(|U^*|\) may be undercounted, and M with it. The verdict does not change: the dump is far larger than any plausible cause set.

Reading the result

The audit box shows the three axes side by side. F and S sit at the ceiling. M sits near the floor. That contrast is the whole result. The figure shows the activity (variance) of every RAM byte over the recording, with the candidate bytes marked: many bytes change over time, far more than the handful the oracle marks as causal for the output. Read A8 as the yardstick for the other methods. Any method that claims to explain should name fewer things than this dump while keeping F and S high. A method that cannot beat the dump on M has described, not explained.

Pitfalls

  • Completeness is not understanding. A record that contains every cause also contains every non-cause, with no way to tell them apart.
  • Faithfulness alone is a weak score. Any explanation can reach F = 1 by naming everything. Always report a size or minimality measure next to it.
  • The sufficiency check here is easy. Restoring a state into the machine it came from is an identity operation; it shows the recorder loses nothing, not that the state is explanatory.
  • The true cause set is only as good as the search. Candidate bytes, three poke values and one horizon bound \(U^*\). A wider search might find more causes, which would raise M somewhat.

How it's scored

The score that matters for this method is minimality, not faithfulness. Recording the whole state is perfectly faithful, because it contains every cause, and perfectly sufficient, because it holds the whole machine and can predict any intervention. So F and S are both at the ceiling by construction. Minimality is defined as the size of the true minimal cause set divided by the size of the set the explanation names. The whole-state dump names all 128 RAM cells, while the true cause of any output is a handful of them, so the ratio is tiny and the minimality is very low. That is the whole point of including this baseline: a complete record is faithful and sufficient yet says nothing in particular, because it withholds nothing. The grading is always against the intervention oracle, which supplies the true minimal set. There is no sprite-position hard-case here; the method makes no positional claim. The audit box reports the exact per-axis triad, F, S, and M, read straight from the leaderboard, so you can see faithfulness and sufficiency at the ceiling beside a minimality near the floor.

The score is measured against the §1 intervention oracle — never against another interpretability method. F (faithful) is always vs the oracle; see the execution stack. How each of F / S / M is actually computed for this method (and whether it matches the paper) is in the box just below; the numbers are in the In the audit box under it.

Call stack — how it runs on jutari / jaxtari

The path from this method's runner (run_game) into the bit-exact VCS substrate, and the computation it involves. Every step links to the exact source on main. From callstack_phaseA.json.

Applied on the substrate

  1. assemble the shared gameplay-state testbed + cause-density gate — build_a8_shared_state(game) -> build_shared_testbed(game; ...) runner
  2. build_shared_testbed definition: booted checkpoint + shared output + gate — function build_shared_testbed(game; ...) runner
  3. cause-density gate counts causes with |Delta_y|>floor via the oracle — cause_density = count(>(floor), deltas) runner
  4. boot the real ROM and replay to the target frame (runner-local boot_replay) — boot_replay(game, actions, target_frame) runner
  5. record the WHOLE state (128 RAM + 64 TIA) per frame across the trajectory — record_whole_state(game, actions) runner
  6. step the real emulator one frame per action while recording — env_step!(env, Int(actions[t])) jutari

The computation

  1. whole-state restore: write the full recorded 128-byte RAM back over the baseline checkpoint (the whole-state 'readout') — restore_whole_ram(checkpoint, ram) runner
  2. whole-state sufficiency (method under test): does restoring the ENTIRE recorded RAM reproduce the exact frame (RAM+screen) — verify_wholestate_sufficiency(checkpoint, at_target) runner
  3. minimal-set sufficiency (positive control): restore ONLY the oracle-causal cells and check the frame is reproduced (contrast that makes over-recording measurable) — verify_minimal_sufficiency(checkpoint, at_target, causal_idx) runner
  4. oracle-causal importance per cell (defines the minimal causal set) — oracle_causal_importance(checkpoint, tail, cands, at_target) runner

Scored against the exact intervention oracle Δy(u): run_intervention(checkpoint, actions, target_frame, horizon, cause).
