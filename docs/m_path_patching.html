Path patching / IOI circuit

Wang et al. 2022; Goldowsky-Dill et al. 2023

← back to the method catalogue

What it does?

Path patching recovers a circuit by patching along specific routes. Rather than measuring whether one internal value matters overall, it patches a value only where it flows along a chosen path to the output, so it can separate a direct effect from an indirect one that passes through other components. This is the technique behind the well-known indirect-object-identification circuit in GPT-2, where it isolated exactly which heads send signals to which. We apply it to the VCS by patching along directed edges of the candidate data-flow and comparing the recovered edge set to the true routine from the disassembly. The idea is powerful because it targets the wiring, not just the nodes. On the VCS its limit is recall in a single frame. When we run it as a one-step directed do-operation, it recovers only the paths that carry a surviving signal in that single step. Many true dependencies are re-derived within the frame through other cells, so a one-step path does not carry them and the method misses them. On some games where the direct circuit is genuinely empty it matches perfectly; on others it recovers little. Path patching is thus precise about what it finds but silent about dependencies that flow through intermediate cells, a recall limit we can measure exactly against the known routine.

The idea in plain words

Activation patching tells you that a component matters. It does not tell you how its influence reaches the output. Component A might act on the output directly, or it might only matter because it changes component B, which then changes the output. A circuit is the answer to that question: the small set of components and the edges (connections) between them that carry out a behaviour. To find edges you need a sharper tool.

Path patching is that tool. You change a sender component, but you let the change reach only one chosen receiver. Every other component downstream of the sender is held at the value it had in the normal run. If the output still moves, the signal must have travelled along the sender→receiver edge. This is how Wang et al. mapped the indirect-object-identification (IOI) circuit in GPT-2: which attention heads send which information to which other heads to complete “When Mary and John went to the store, John gave a drink to…” with “Mary”. On the VCS the true wiring between memory cells can be measured exactly, so we can check how much of it a path patch actually recovers.

How it works on a neural network

Think of the network as a directed graph of components. A transformer’s components all read from and write to the residual stream, so every earlier head can influence every later one. Pick a sender \(s\) and a receiver \(r\). Path patching runs the clean input \(x\) with three rules: \(s\) takes its value from the corrupted input \(\tilde x\); the receiver \(r\) is recomputed normally, so it sees the corrupted \(s\); and every other component that \(s\) could reach is frozen to its clean value. Then

\[ \Delta_{s \to r} \;=\; y\big(x \,\big|\, s := s(\tilde x),\; \text{others frozen},\; r \text{ recomputed}\big) \;-\; y(x). \]

A non-zero \(\Delta_{s\to r}\) means the edge \(s \to r\) carries part of the behaviour. Repeating this over pairs, working backwards from the output, builds the circuit. The result is scored as a set of edges.

Toy example. Let \(b = 2a\), \(c = a + b\), and output \(y = c\). Clean \(a = 1\): \(b = 2\), \(c = 3\). Corrupt \(a := 2\). Plain activation patching of \(a\) gives \(b = 4\), \(c = 6\), so \(\Delta_a = 3\). Now path-patch the edge \(a \to b\): let \(b\) see \(a = 2\) (so \(b = 4\)), but freeze \(a\)’s direct input to \(c\) at its clean value 1. Then \(c = 1 + 4 = 5\) and \(\Delta_{a\to b} = 2\). Path-patch the direct edge \(a \to c\) instead: \(b\) stays at 2, \(c = 2 + 2 = 4\), \(\Delta_{a\to c} = 1\). The total effect of 3 splits into an indirect part (2, via \(b\)) and a direct part (1). That split is what node-level patching cannot give you.

Recipe

  1. Choose clean and corrupted inputs and a metric, as for activation patching.
  2. Pick a sender component \(s\) and a receiver \(r\).
  3. Run the clean input with \(s\) set to its corrupted value; freeze every other component downstream of \(s\) at its clean value; let only \(r\) recompute.
  4. Run the rest of the network and record \(\Delta_{s\to r}\).
  5. Repeat over sender/receiver pairs, starting from the output and moving backwards; keep the edges with large effects.
  6. Score the recovered edge set (precision, recall, F1) against a reference, or test it with ablations.

How we apply it to the VCS

The nodes are the game’s candidate RAM cells. Everything starts from the shared gameplay checkpoint at \(f^*\) with a 15-frame horizon. The first frame of the horizon is the sender→receiver hop, using the gameplay stream’s own next action.

  1. One path patch \(i \to j\): copy the checkpoint, write the sender value into cell \(i\), step one frame, then restore every candidate cell except \(j\) to its clean frame-\(f^*{+}1\) value. Run the remaining 14 frames. The edge fires if cell \(j\) ends up different from the clean run.
  2. Recovered circuit. One sender value per edge (base+17), the classical single-shot path patch, over all ordered pairs of cells.
  3. True routine. The same edge-restricted operation, but with three sender values. This is the faithful direct circuit the method targets. A separate transitive graph (perturb a cell, run the full horizon, see which cells change) is recorded for context only.
  4. Score. Edge precision, recall and F1 of the recovered circuit against the true routine, with self-edges excluded.
  5. Positive control. Re-deriving the circuit with the exhaustive value set must give F1 = 1, proving the scorer rewards a faithful circuit.

Two differences from the transformer original matter. First, our “layer” is a whole frame of thousands of CPU instructions, and a cell can be read and rewritten many times inside it. Second, we freeze only the candidate cells, not every byte, CPU register or TIA register. A signal can also leak through those unfrozen parts. The runner also counts transient receivers: cells the program recomputes from scratch, so no single-frame path into them can survive to the end of the horizon.

Reading the result

Each game’s figure compares two adjacency matrices: the recovered edges and the true routine. Expect low recall on most games. A single sender value often fails to trip an edge that another value would. Many cells are also rebuilt by the program within the frame through other cells, so the one-step path carries no surviving signal. On games where the direct circuit is genuinely empty the method trivially matches it. On others, including the Pong state shown here, it can recover almost nothing. The positive control shows this is a real limit of the single-shot method, not a scoring bug.

Pitfalls

  • Which nodes you freeze defines the answer. Freezing too few lets the signal leak around the chosen path; freezing too many can break the computation. On the VCS we freeze only candidate cells.
  • One corruption value is not enough. An edge can carry a signal only for some values (a branch that triggers above a threshold). Single-shot recall is limited by that.
  • Coarse layers. A VCS frame contains many reads and writes of the same cell. A one-frame hop merges several real edges into one, or hides them.
  • Metric fragility. Miller et al. show that circuit faithfulness scores in transformers change a lot with the ablation type and the metric. Report your choices.
  • Cost grows with pairs. One re-run per sender–receiver pair and value: quadratic in the number of nodes. This is why ACDC and edge attribution patching exist.

How it's scored

The score is the F1 of the recovered path or circuit against the true routine's data-flow. We patch along directed edges of the candidate data-flow and compare the recovered edge set to the true routine from the disassembly, taking the harmonic mean of edge precision and recall. The grading is always against the intervention oracle's true wiring. Faithfulness for this method is that circuit F1. Run as a single-frame, one-step directed do-operation, the method recovers only the paths that carry a surviving signal in that single step. Many true dependencies are re-derived within the frame through other cells, so a one-step path does not carry them and recall suffers, which is the main limit the score reflects. On some games the direct circuit is genuinely empty and the method matches it perfectly; on others it recovers little. There is no sprite-position hard-case here, because the output is a circuit, not a coordinate. The grading is always against the oracle, never against another method. The audit box reports the measured triad across the scored games, so the F1 is an average over the scored set. Path patching is precise about the paths it finds but silent about dependencies that flow through intermediate cells.

The score is measured against the §1 intervention oracle — never against another interpretability method. F (faithful) is always vs the oracle; see the execution stack. content-F and position-F are n/a for this method. The content-vs-position split applies only to pixel-attribution methods — those that produce an attribution map over the framebuffer, whose score can be read separately on the smooth content outputs and the discrete position outputs (where the naive gradient is provably zero). This method does not attribute to a pixel output; it is graded by its own fidelity metric (path_circuit_F1_vs_true_routine), reported as the F column, so there is no content or position regime to separate.

On a game where the method names nothing (|Û| = 0 — it discovers no circuit, its attribution map is all-zero, or it decodes no cell), that ratio is undefined, so M is left blank rather than scored.
