Phase C · mechanistic interpretability

ACDC — automatic circuit discovery

Conmy et al. 2023

← back to the method catalogue

What it does?

ACDC automates circuit discovery. Instead of a human proposing a circuit and patching it by hand, ACDC starts from the full computational graph and prunes edges one at a time. It removes an edge by resample-ablation, replacing the signal on that edge with a resampled value, and keeps the edge only if removing it hurts performance beyond a threshold. Sweeping the threshold traces out a family of candidate circuits. The output is a minimal subgraph that, in principle, carries the computation, found automatically. This is one of the main tools for scaling mechanistic interpretability beyond hand analysis. We apply it to the VCS by pruning the candidate data-flow graph and comparing the discovered circuit to the true routine over a threshold sweep. The VCS gives ACDC an unusually fair test, because we have the exact wiring and can also run a positive control that prunes under exhaustive exact interventions. Against that control ACDC's shortfall is a real property of single-shot discovery, not a broken scorer. It recovers a fraction of the true edges: its precision is reasonable but its recall is limited, because dependencies re-derived through other cells survive the resample and are pruned away. On one game it recovers a perfect, minimal circuit that nonetheless fails to regenerate the behaviour, which is one of the paper's key separations between a correct graph and a working computation.

The idea in plain words

A trained network is a huge web of computations. Mechanistic interpretability hopes that a specific behaviour, such as “complete the name in this sentence”, is carried by a small sub-web of that computation. That sub-web is called a circuit. For years, people found circuits by hand: guess a component, knock it out, look at the output, repeat. That is slow and depends on the researcher's intuition.

ACDC automates the search. Draw the whole model as a graph: nodes are components (attention heads, MLP blocks), and an edge means “this node's output is an input to that node”. Then walk over the edges and cut each one in turn. If cutting an edge barely changes the model's output, the edge is not needed and is pruned for good. If it changes the output by more than a threshold \(\tau\), it stays. What survives is the discovered circuit. Turning the dial \(\tau\) gives a whole family of circuits, from tiny (large \(\tau\)) to almost the full model (small \(\tau\)).

How it works on a neural network

“Cutting” an edge does not mean setting it to zero. Zero is often an input the model has never seen. ACDC instead uses resample ablation: the signal on the edge is replaced by the value it takes on a corrupted input (for example, the same sentence with a different name). Let \(G\) be the full model, \(H\) the current candidate circuit, and \(H \setminus e\) the circuit with edge \(e\) cut. ACDC measures how far the output distribution moves, with the Kullback–Leibler divergence \(D_{\mathrm{KL}}\) (a standard distance between two probability distributions), and prunes \(e\) if

\[ D_{\mathrm{KL}}\big(G \,\|\, H\setminus e\big) \;-\; D_{\mathrm{KL}}\big(G \,\|\, H\big) \;<\; \tau . \]

Edges are visited from the output backwards, and every prune is kept, so later decisions are made on an already-thinned graph.

Toy example. A network has input \(x\), two hidden units \(A\) and \(B\), and output \(y\). The four edges are \(x\!\to\!A\), \(x\!\to\!B\), \(A\!\to\!y\), \(B\!\to\!y\). Resample-ablating each one moves the output by 1.4 (for \(A\!\to\!y\)), 0.02 (\(B\!\to\!y\)), 1.0 (\(x\!\to\!A\)) and 0.5 (\(x\!\to\!B\)). With \(\tau = 0.1\), \(B\!\to\!y\) is pruned. Now \(B\) feeds nothing, so cutting \(x\!\to\!B\) changes nothing either, and it is pruned too. The circuit is \(x \to A \to y\). Note how the second decision depended on the first: that is the iterative part.

Recipe

  1. Choose a behaviour, a set of clean inputs, matching corrupted inputs, and an output metric (KL divergence or a logit difference).
  2. Write the model as a graph of components and start with every edge present.
  3. Visit edges from the output backwards. For each edge, replace its signal by the corrupted-input value and re-run the model.
  4. If the metric moves by less than \(\tau\), delete the edge permanently; otherwise keep it.
  5. Repeat for several \(\tau\) values. Each gives one candidate circuit.
  6. Judge the circuits: compare to a known circuit (precision/recall of edges), or check that the circuit alone reproduces the behaviour.

How we apply it to the VCS

On a language model nobody knows the “real” circuit, so ACDC can only be judged against other human guesses. On the VCS the program's data flow can be measured exactly, because jutari re-runs the ROM bit-for-bit. Our runner acdc.jl does the following:

  1. State. It boots the game, plays the shared seeded random-action stream for 90 frames, and checkpoints the machine at \(f^*\). The remaining 15 frames of the stream are the tail. It asserts that two fresh boots give identical RAM and screen before scoring anything.
  2. Edge effects. For every candidate cell \(i\), it writes one corrupted value into cell \(i\), plays the tail once, and reads every candidate cell \(j\). That fills a whole row of the effect matrix \(E[i,j]\) with one re-run. The corrupted value comes from a donor run that switches to the RIGHT action at \(f^*\); because that donor is identical to the clean run up to \(f^*\), the synthetic fallback base+17 is what is normally used. The record counts how often the donor really diverged.
  3. Threshold sweep. The discovered circuit at \(\tau\) is every off-diagonal pair with \(E[i,j] > \tau\). Thresholds are placed between consecutive distinct effect sizes, so the sweep walks from “every edge with any effect” down to “nothing”.
  4. Scoring. Each circuit is compared with the exhaustive true graph: precision, recall, F1, plus an ROC curve and its area. The headline is the best F1 over the sweep.
  5. Sufficiency. At the best \(\tau\), every source cell with no surviving outgoing edge is resample-ablated at the same time, the tail is replayed, and we count the fraction of candidate cells that still match the clean run (“scrubbing-preserved performance”).
  6. Positive control. Running the same keep-rule with the full oracle value set and \(\tau=0\) reproduces the true graph exactly. This proves the scorer can reward a perfect discovery.

Where we differ from the original. Our ACDC is single-shot: one ablation per source, then pure thresholding. It does not prune iteratively, so it skips the “dangling node” step of the toy example. The metric is a byte difference, not a KL divergence. And an edge is a total effect over 15 frames, because RAM cells interact through many CPU instructions, not through one weight. These choices make it cheap and comparable with the oracle. They also explain a typical failure: a single corrupted value can miss edges that only fire for other values, which costs recall.

Reading the result

The figure shows the threshold sweep: precision and recall of the discovered edges against the true data-flow graph as \(\tau\) falls. A perfect method would hit the top-right corner at some \(\tau\); the positive control does exactly that. Expect ACDC's curve to sit lower. Precision is usually decent, because an edge with a visible effect under one corruption is usually real. Recall is the weak side: an edge that only shows up for a different value, or that the program re-derives from another cell, looks dead under a single resample and gets pruned. Read the scrubbing-preserved number beside it: a circuit can score a good F1 and still fail to reproduce the behaviour on its own.

Pitfalls

  • One corruption is not all corruptions. An edge whose effect depends on the value chosen can be invisible under the one resample used. The exhaustive oracle tries several values; ACDC tries one.
  • The threshold is a free parameter. There is no correct \(\tau\). Reporting only the best-F1 point uses the ground truth to pick it, which a real network user cannot do.
  • Total vs direct effects. On the VCS an edge means “influences after 15 frames”. Indirect paths (\(i\to k\to j\)) appear as edges \(i\to j\) too, in both the discovered and the true graph.
  • Minimal is not sufficient. A small, clean-looking circuit can still fail when everything outside it is scrubbed. Always check sufficiency separately (see causal scrubbing).
  • Metric choice changes the circuit. Miller et al. show that small changes in how ablations and metrics are defined change which circuit is found. Our byte-difference metric is one choice among many.

How it's scored

The score is the best F1 of the auto-discovered circuit against the true data-flow over a threshold sweep. ACDC prunes edges by resample-ablation, keeping an edge only if removing it hurts performance beyond the current threshold, and sweeping the threshold traces a family of candidate circuits from which we take the best F1 against the true routine. The grading is always against the intervention oracle's true wiring. Faithfulness for this method is that best F1, and it is partial: precision is reasonable but recall is limited, because dependencies re-derived through other cells survive the resample and get pruned away. A positive control runs the identical pruning under exhaustive exact interventions and reaches a perfect F1 on every game, so the shortfall is a real measurement of single-shot discovery, not a broken scorer. There is no sprite-position hard-case here; the output is a circuit. One of the paper's key separations comes from this method: on one game ACDC recovers a perfect, minimal circuit that nonetheless fails to regenerate the behaviour under held-out interventions, so sufficiency drops well below faithfulness. The grading is always against the oracle. The audit box reports the measured triad, so you can see faithfulness beside a lower sufficiency on the same discovered graph.

The score is measured against the §1 intervention oracle — never against another interpretability method. F (faithful) is always vs the oracle; see the execution stack. How each of F / S / M is actually computed for this method (and whether it matches the paper) is in the box just below; the numbers are in the In the audit box under it.

content-F and position-F are n/a for this method. The content-vs-position split applies only to pixel-attribution methods — those that produce an attribution map over the framebuffer, whose score can be read separately on the smooth content outputs and the discrete position outputs (where the naive gradient is provably zero). This method does not attribute to a pixel output; it is graded by its own fidelity metric (discovered_circuit_best_F1_vs_true_dataflow), reported as the F column, so there is no content or position regime to separate.

M is n/a on 3 of these games. Minimality is M = |U*|/|Û|, the size of the true minimal cause set over the size of the set the method actually names. On a game where the method names nothing (|Û| = 0 — it discovers no circuit, its attribution map is all-zero, or it decodes no cell), that ratio is undefined, so M is left blank rather than scored. Applied on the substrate

  1. Boot the real ROM with the xitari-parity reset (60 NOOP + 4 RESET) before any replay — env_reset!(env; boot_noop_steps = 60, boot_reset_steps = 4) jutari

  3. Assemble the shared seeded-random-action gameplay-state testbed (checkpoint at f*, causes, shared screen output, cause-density gate) — build_shared_testbed(game; ... run_intervention = O.run_intervention, soft_ram_peek = soft_ram_peek, ...) via build_acdc_shared_state runner
  4. Freeze byte-exact RAM + cropped screen out of the env at a frame — snapshot(env::StellaEnvironment, frame::Integer) jutari

The computation

  1. Pick the corrupted resample value per source (donor byte where it diverges, else base+17) — resample_value(clean_val::Int, donor_val::Int) runner
  2.
