RISE

Petsiuk et al. 2018

← back to the method catalogue

What it does?

RISE explains a black box by random masking. It generates many random masks, applies each to the input, records the output for each masked version, and then forms an importance map as the output-weighted average of the masks. Inputs that tend to be present when the output is high receive high importance. The method needs no gradients and no access to the model's internals; it only needs to query the output, which is why it is popular for truly opaque systems. The intuition is a Monte-Carlo estimate of each input's marginal effect. We apply it to the VCS by drawing hundreds of random masks over the candidate causes, re-running the program for each, and averaging. Because it perturbs and re-runs the real machine, it works on a sprite's position where gradients are dead, unlike the gradient family. Its accuracy depends on the number of masks and on how informative random masking is for a given output. On smooth content outputs it does reasonably well. On a discrete position output, masking a single discrete cause is less informative, so the estimate is noisier and its faithfulness drops. RISE is a clean example of a perturbation method that is genuinely causal in its mechanism but pays for using random rather than targeted interventions.

The idea in plain words

Occlusion hides one part at a time. RISE hides many parts at once, at random. Throw a random pattern of holes over the photo (about half the pixels hidden), run the network, write down the dog score. Repeat a few hundred times with fresh random patterns. Now ask, for each pixel: when this pixel happened to be visible, how high was the score on average? Pixels the network needs will be visible mostly in the high-scoring runs. Pixels it ignores will be visible in high and low runs alike.

This is a Monte-Carlo estimate: instead of trying every possible pattern (there are \(2^n\)), you average over random samples, and the estimate gets better as you draw more. RISE is a black-box method like occlusion. Because many parts are hidden together, it can notice parts that only matter in combination, which occlusion cannot. The price is noise: with few masks, the map is grainy.

How it works on a neural network

Draw \(N\) random binary masks \(m_1,\dots,m_N \in \{0,1\}^n\). Each entry is an independent coin flip: kept (\(1\)) with probability \(p\), hidden (\(0\)) otherwise (a Bernoulli variable). Run the model on each masked input, \(y_k = f(x \odot m_k)\). The importance of input \(i\) is

\[ S_i \;=\; \frac{1}{N\,p}\sum_{k=1}^{N} y_k \, m_{k,i} \;\;\approx\;\; \mathbb{E}\big[\,y \mid m_i = 1\,\big] . \]

That is the average output over the masks that kept input \(i\): a conditional expectation. The \(1/(Np)\) factor turns the sum into that average, because about \(Np\) masks keep \(i\). On images, RISE draws small grids, upsamples them smoothly and shifts them randomly, so the holes are blobs rather than single pixels.

Toy example. \(f(x) = 4x_1x_2 + x_3\) at \(x=(1,1,1,1)\) (\(x_4\) unused), \(p = 0.5\). Enumerate all 16 masks instead of sampling. When \(x_1\) is kept, \(x_2\) is kept half the time and \(x_3\) half the time, so \(\mathbb{E}[y\mid m_1{=}1] = 4\cdot0.5 + 0.5 = 2.5\). Likewise \(S_2 = 2.5\), \(S_3 = 4\cdot 0.25 + 1 = 2\), \(S_4 = 1.5\). The unused \(x_4\) gets exactly the overall mean \(\mathbb{E}[y] = 1.5\). Subtract it and you get \((1, 1, 0.5, 0)\): the interaction pair ranks first, \(x_3\) second, \(x_4\) is zero. With \(p = 0.5\) this centred score is half the average change caused by switching \(x_i\) on (the Banzhaf value, a close relative of the Shapley value). Note: occlusion on the same toy gives \((4,4,1,0)\), and both agree on the ranking here.

Recipe

  1. Choose the output \(y\), the number of masks \(N\), the keep-probability \(p\) and what “hidden” means (here: set to 0).
  2. Draw a random mask: keep each input with probability \(p\).
  3. Hide the inputs whose mask bit is 0, run the model, record \(y_k\). Repeat \(N\) times.
  4. For each input, average \(y_k\) over the masks that kept it: \(S_i = \frac{1}{Np}\sum_k y_k m_{k,i}\).
  5. Normalise the map (subtract the mean) and display it.

How we apply it to the VCS

The VCS version follows the paper's formula one-to-one; only the “image” changes. The universe is the list of candidate RAM cells. Each of the \(N = 500\) masks keeps every cell with probability \(p = 0.5\). For each mask, masked_read_y copies the checkpoint, zeroes the dropped cells with intervene_ram!, plays the recorded 15 actions with env_step!, and reads \(y\). Those 500 real-emulator runs are the whole cost of the method. rise_importance then computes \(\frac{1}{Np}\sum_k y_k m_{k,i}\).

From cells to causes. The oracle scores causes, not cells. rise_attr_per_cause centres the cell scores by subtracting their mean across cells, takes the absolute value, and gives each RAM cause the score of its cell (so a byte's :set and :occlude causes get the same value). TIA and joystick causes get 0, because RISE never touches them.

Convergence. RISE is a Monte-Carlo estimate, so the runner also rescores the map using only the first \(N/8\), \(N/4\), \(N/2\) masks of the same pool. That shows how the agreement with the oracle grows with compute, without drawing new masks.

How is this different from the oracle? Three ways. (1) Joint masks: in every run about half the cells are zeroed at once, so each \(y_k\) mixes many effects; the oracle changes one cause at a time. (2) Averaging: RISE reports an average over random contexts, the oracle a single exact difference at the real state. (3) One direction: RISE only ever sets cells to 0. On a content byte that responds smoothly to many cells, the average is informative. On the position output, the effect of one cell is often an all-or-nothing jump that depends on which other cells are zeroed with it, so the average is noisier.

Reading the result

Bars are RISE scores per cause, next to the oracle's true effect. Two features are built in: TIA and joystick causes are always zero for RISE, and the two causes of one byte always share a height. Beyond that, compare the tallest bars. On content outputs expect reasonable agreement; on position outputs expect a noisier map with a weaker match. The convergence numbers in the record show whether more masks would still help: if agreement is still rising from \(N/2\) to \(N\), the estimate has not settled.

Pitfalls

  • Monte-Carlo noise. The variance falls only like \(1/N\). Few masks give a grainy, seed-dependent map.
  • Average over strange contexts. With \(p=0.5\), every run zeroes about half the cells. The score answers “how much does this cell help in a heavily damaged machine?”, which can differ from its effect in the real, intact state.
  • Centring across cells. Our map subtracts the mean of the cell scores, not the global mean output. When most cells are inert, the two are about the same (inert cells score the global mean). When most cells matter, the across-cell mean is pulled up and the absolute value can mis-rank cells.
  • Masks are the input type. On images, the blob size of the upsampled masks is a hidden hyper-parameter. Here the masks are over a fixed candidate list; RAM bytes outside it cannot be credited.

How it's scored

The score is the Pearson correlation of the RISE importance map with the oracle's exact causal map, reported raw, and the grading is always against the intervention oracle. RISE forms its map by averaging the output over hundreds of random masks, each a real re-run of the machine, so it is a genuine perturbation method and works on a sprite's position where the gradient family scores zero. That is why it does not collapse on the position regime. Its faithfulness is moderate: on smooth content outputs the random-mask average recovers the true causes reasonably well, but on a discrete position output masking a single discrete cause is less informative, so the estimate is noisier and the position score drops below the content score. The accuracy also depends on how many masks are drawn, since RISE is a Monte-Carlo estimate. The grading is always against the oracle, never against another method. The audit box reports the measured all-regime faithfulness across the 44 scored games, which averages the stronger content result and the weaker position result. RISE shows that a truly perturbation-based method can beat the gradient family on discrete outputs while still paying for using random rather than targeted interventions.

The score is measured against the §1 intervention oracle — never against another interpretability method. F (faithful) is always vs the oracle; see the execution stack. How each of F / S / M is actually computed for this method (and whether it matches the paper) is in the box just below; the numbers are in the In the audit box under it.
