Guided Backprop

Springenberg et al. 2015

← back to the method catalogue

What it does?

Guided backpropagation is a variant of saliency that changes how the signal flows backward through the network. At each rectifier it keeps only the positive contributions and zeroes the negative ones, on both the forward activation and the backward gradient. The effect is a much sharper, cleaner-looking saliency map, which is why the method became popular for visualising what a network 'sees'. The intuition is that suppressing the negative evidence isolates the features that positively drive the output. We apply the same rectified-backward rule to the VCS and correlate the resulting map with the true causal map. A well-known concern, raised by Adebayo and colleagues, is that guided backprop can act more like an edge detector than a true explanation, producing similar maps even when the model is randomised. We run exactly that sanity check on the machine itself. On smooth content outputs the method partly tracks the true cause. On a sprite's position it hits the gradient wall: the position is a discrete strobe-timed step, so the underlying gradient is zero, and the rectified backward path leaves it at zero here rather than restoring any signal. Combined with its failure of the randomisation check, this makes guided backprop a revealing case: it looks sharp and convincing yet does not depend on what the program actually computes.

The idea in plain words

Vanilla saliency maps of image classifiers look grainy. Positive and negative gradient signals mix as they flow back through the network. Guided backpropagation changes one rule in the backward pass to clean this up. At every ReLU (rectified linear unit, \(\max(0, z)\), the standard on/off nonlinearity of deep nets) it lets a gradient through only if the unit was active in the forward pass and the gradient arriving from above is positive. Negative signals (“this feature argues against the class”) are thrown away.

The result looks spectacular: crisp, edge-like pictures of the object. That is why the method became popular. But it is no longer the gradient of anything. It is a hand-modified signal. Adebayo et al. (2018) asked a simple question: does the map change if we destroy the model? For guided backprop it barely does. The map behaves more like an edge detector applied to the input than an explanation of the network. This test, the model-randomisation sanity check, is part of our experiment, run on the machine itself.

How it works on a neural network

Take one ReLU unit \(h = \max(0, z)\) and let \(g = \partial y/\partial h\) be the gradient arriving from above. The three backward rules differ only in what they send down to \(z\):

\[ \text{backprop: } \mathbb{1}[z>0]\,g, \qquad \text{deconvnet: } \mathbb{1}[g>0]\,g, \qquad \text{guided: } \mathbb{1}[z>0]\,\mathbb{1}[g>0]\,g . \]

Guided backprop combines the two masks. Applied at every ReLU of the network it yields a map \(G(x)\) that, unlike saliency, is not the derivative \(\nabla f(x)\).

Toy example. Two inputs, two hidden ReLUs, one output: \(h_1 = \max(0, 2x_1 + x_2)\), \(h_2 = \max(0, x_1 - x_2 + 1)\), \(y = h_1 - h_2\). At \(x = (1, 1)\): \(h_1 = 3\), \(h_2 = 1\), \(y = 2\). Both units are active. From above, \(\partial y/\partial h = (1, -1)\).

  • Vanilla gradient: \(1\cdot(2, 1) + (-1)\cdot(1, -1) = (1, 2)\). It says \(x_2\) matters most.
  • Guided: the \(-1\) arriving at \(h_2\) is negative, so it is zeroed. Only \(1\cdot(2,1) = (2, 1)\) survives. It says \(x_1\) matters most.

The ranking flipped. \(h_2\) inhibits the output and \(x_2\) acts partly by reducing that inhibition. Guided backprop discards inhibition, so it cannot see this. Check the truth directly: raising \(x_2\) by 0.1 raises \(y\) by 0.2, raising \(x_1\) by 0.1 raises it by only 0.1. Here the vanilla gradient was right and the “cleaner” map was wrong.

Recipe

  1. Run the forward pass and record which ReLUs are active (\(z > 0\)).
  2. Start the backward pass from the scalar output \(y\), as in vanilla saliency.
  3. At every ReLU, pass the gradient down only where \(z > 0\) and the incoming gradient is \(> 0\); set everything else to 0.
  4. Continue to the input. Display the (usually absolute) result as a heat-map.
  5. Sanity check (Adebayo): randomise the model's weights, recompute the map, and verify it changes. A map that stays the same cannot be explaining the model.

How we apply it to the VCS

Our substrate has no deep stack of ReLUs. The runner says so plainly, and implements guided backprop as the rectification rule \(g \mapsto g\odot\mathbb{1}[g>0]\) applied to the gradient \(\partial y/\partial u\) over the RAM vector \(u\), followed by an absolute value. It returns the guided map and the vanilla \(|\partial y/\partial u|\), so the effect of the rule can be measured directly.

  • Content output. \(y = \) soft_ram_peek(ram, idx), whose gradient is the one-hot vector \(e_{\text{idx}}\). It has no negative entries, so there is nothing to suppress: the guided map equals vanilla saliency exactly. The runner records this as guided_equals_vanilla. The byte idx is the candidate the oracle shows to be most causally active, the same choice as the SmoothGrad runner, so only the backward rule differs.
  • Is the rule real? To show it is not a no-op stub, guided_demo_rectifies applies it to a small linear surrogate with mixed-sign weights and asserts that every negative entry is zeroed.
  • Position output. The naive gradient is zero (sprite position is set by strobe timing). The bilinear sampler restores one, but its sign depends on which side of the screen cell the sprite edge sits: moving the sprite can reduce the cell's occupancy. A negative slope is exactly what the guided rule deletes. So guided backprop can throw away the very gradient the sampler restored. The runner reports the raw sampler gradient next to the rectified one.
  • The Adebayo check. randomize_rom fills the cartridge with random bytes but keeps the last 6 bytes of each 4 KB bank (the 6502 reset/IRQ/NMI vectors). Three randomised programs are booted and replayed to \(f^*\). The runner counts how many RAM bytes differ from the real game, recomputes the guided map, and measures its cosine similarity to the real map. The scrambled programs reach very different RAM states. Yet the content map is identical, because the one-hot Jacobian does not depend on what the program computed. The runner classifies this as a genuine failure (“model-invariant saliency, constant Jacobian”), not as a harness error.
  • Scoring is shared with the other gradient methods: correlation and precision@3 against the oracle, and deletion/insertion curves re-run on the real ROM, plus an oracle-vs-itself control.

Reading the result

On the content output the guided bars are the vanilla saliency bars, exactly. Any agreement with the oracle is saliency's agreement. On the position output the map is often empty, either because the naive gradient is zero or because the rule removed a negative sampler slope. Then look at the sanity-check box. A cosine similarity near 1 between the real and the scrambled-program maps means the map does not depend on the program. A faithful map must change when the model is destroyed; this one stays the same. The oracle, by contrast, re-runs the program and would see the difference at once.

Pitfalls

  • Not a gradient. Guided backprop is a modified signal. It has no completeness property and no clear causal meaning.
  • Discards inhibition. Inputs that matter by suppressing a unit are invisible to it, as the toy example shows.
  • Model-insensitive. Adebayo et al. and Nie et al. showed that guided maps largely reconstruct the input image and change little when weights are randomised. On the VCS content read the map does not change at all.
  • Substrate mismatch. The VCS has no ReLU layers, so here the method collapses to rectified vanilla saliency. That is an honest limit of transferring a network-specific rule to a different system.
  • Looks are misleading. Sharper is not truer. Only the intervention oracle decides.

How it's scored

The score is the Pearson correlation of the guided-backprop map with the oracle's exact causal map, reported raw, and the grading is always against the intervention oracle. On smooth content outputs the rectified backward pass partly tracks the true cause. The hard case is a sprite's position: it is a discrete strobe-timed step, so the naive gradient is provably zero, and here the method's rectified path leaves it at zero rather than restoring any signal. On top of that, guided backprop fails the Adebayo program-randomisation sanity check on the machine itself. We scramble the ROM so the program boots to a completely different state, and the content-path map stays essentially unchanged, because its Jacobian is a constant one-hot pointing at the read index, independent of what the program computes. A faithful explanation must change when the model changes; this one does not. So even where it looks sharp, it is model-invariant, which the intervention oracle exposes at once by distinguishing the two programs. Between the zero position gradient and the failed sanity check, its cross-game faithfulness stays low. The audit box reports the measured all-regime faithfulness across the scored games.

The score is measured against the §1 intervention oracle — never against another interpretability method. F (faithful) is always vs the oracle; see the execution stack. How each of F / S / M is actually computed for this method (and whether it matches the paper) is in the box just below; the numbers are in the In the audit box under it.
