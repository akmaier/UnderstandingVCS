What it does?

Granger causality infers direction from timing. The rule is simple: if the past of signal A helps predict the future of signal B beyond B's own past, then A is said to Granger-cause B. It is widely used in neuroscience and economics to draw directed influence graphs from recorded time series, without any intervention. We apply it to the VCS by treating the CPU, TIA, and RIOT activity as time series and asking which components predict which. The result is a directed graph of inferred influence that we compare to the true data-flow. The appeal is that it turns passive observation into a causal-looking claim. The deep flaw, on this machine, is that it equates 'happens earlier' with 'is the cause'. The VCS is clock-locked, so almost every signal is predictable from almost every other signal one cycle earlier, whether or not there is a real dependency. Granger causality therefore infers edges everywhere. Neither a longer lag nor a stricter threshold repairs this, because the shared clock creates predictability that is not causation. It is the cleanest demonstration in our battery that precedence is not cause, and that only an intervention can tell them apart.

The idea in plain words

You record two signals over time, say the activity of brain areas A and B. You cannot cut wires or stimulate anything. Can you still say which one drives the other? Clive Granger's idea (1969) is a clever proxy: a cause comes before its effect, and it carries information about the effect. So try to predict B's next value from B's own past. Then add A's past. If the prediction gets clearly better, A is said to Granger-cause B. Run this for every ordered pair and you get a directed graph of “who influences whom”, built purely from passive recordings.

The word “causality” is generous. What the test really measures is temporal precedence plus predictive information. That is not the same as a causal wire. If both A and B are driven by a hidden third signal C, and A sees C a moment earlier than B, then A's past predicts B perfectly, with no wire from A to B at all. This hidden common driver is a confounder. A clock-driven machine like the Atari is full of them. A6 measures how far the Granger graph sits from the true wiring, which on the VCS we can establish by direct intervention.

How it works on a neural network

Neuroscience origin. Granger causality is a workhorse for “directed functional connectivity” in EEG, MEG, LFP and fMRI data (Seth et al. 2015). Jonas & Kording applied it to a simulated 6502 chip and found a graph that bore little resemblance to the real circuit.

Deep-learning analogue. In XAI it is temporal-precedence causal discovery on activation time series: record hidden units of a recurrent network, the residual stream across tokens, or the latent state of an RL agent over steps, then infer which units “drive” which.

The test. For an ordered pair \(x\to y\) and a lag \(p\), fit two linear autoregressions by least squares:

\[ \text{restricted:}\; y_t = a_0 + \sum_{l=1}^{p} a_l\,y_{t-l} + e_t, \qquad \text{unrestricted:}\; y_t = a_0 + \sum_{l=1}^{p} a_l\,y_{t-l} + \sum_{l=1}^{p} b_l\,x_{t-l} + e'_t . \]

With residual sums of squares \(\mathrm{RSS}_r \ge \mathrm{RSS}_u\) over \(n\) usable steps, the Granger statistic and its F-test are

\[ G(x\to y) = \ln\frac{\mathrm{RSS}_r}{\mathrm{RSS}_u}, \qquad F = \frac{(\mathrm{RSS}_r-\mathrm{RSS}_u)/p}{\mathrm{RSS}_u/(n-2p-1)} . \]

An edge \(x\to y\) is declared when the F-test's p-value falls below a significance level \(\alpha\) (usually 0.05).

Toy example. A hidden driver produces random numbers \(d = (3,1,4,1,5,9,2,6)\). Unit \(x\) copies it one step late, unit \(y\) two steps late: \(x_t = d_{t-1}\), \(y_t = d_{t-2}\). So \(x = (\cdot,3,1,4,1,5,9,2)\) and \(y = (\cdot,\cdot,3,1,4,1,5,9)\). Because \(d\) is random, \(y\)'s own past says little about its next value: \(\mathrm{RSS}_r\) is large. But \(y_t = x_{t-1}\) exactly, so adding \(x\)'s past drives \(\mathrm{RSS}_u\) to zero. \(G\) is huge, the p-value is tiny, and the test reports a strong edge \(x\to y\). There is no wire between them: both just read \(d\). Cutting \(x\) would leave \(y\) unchanged. Only that intervention reveals the truth.

Recipe

  1. Record the time series you want to connect (unit activations, region activity, RAM bytes).
  2. Drop constant series: with zero variance the test is undefined.
  3. For every ordered pair \(x\to y\), fit the restricted and unrestricted autoregressions at lag \(p\).
  4. Compute \(G=\ln(\mathrm{RSS}_r/\mathrm{RSS}_u)\) and the F-test p-value.
  5. Declare an edge \(x\to y\) if \(p\le\alpha\) (optionally also \(G\ge\tau\)).
  6. Read the resulting directed graph as the system's influence structure, and here score it against the intervention-defined true graph.

How we apply it to the VCS

The runner A6_granger.jl builds the method's graph and the true graph on the same nodes, then compares them.

  1. The recording. From the shared gameplay state (seeded random actions, checkpoint at frame \(f^*=90\)) it records a trajectory of 150 frames for most games, continuing with NOOP after the gameplay window. a6_record_tape calls env_step! each frame and stores the 128 RAM bytes plus the 64 TIA registers.
  2. Granger, cell scope. run_cell_granger tests every ordered pair of candidate bytes with granger: lag \(p=2\), \(\alpha=0.05\), magnitude floor \(\tau=0\) (so significance alone decides, the textbook rule). The least-squares fits and the F-distribution p-value are written out by hand, so no statistics package is needed.
  3. Granger, subsystem scope. subsystem_activity turns the tape into three change-count series. The CPU series counts changes in RAM bytes 0x00–0x5F, the RIOT series in 0x60–0x7F, the TIA series in its register file. They are scored against a fixed truth: the CPU writes the TIA, and the CPU reads the RIOT.
  4. The true graph. true_dataflow_graph takes the checkpoint at \(f^*\) and, for each candidate byte \(i\), pokes three values (0, base+17, base+37) with intervene_ram!. It re-runs the 15-frame horizon and marks \(i\to j\) for every candidate byte \(j\) that ends up different. A second graph from base+37 alone serves as a held-out probe.
  5. Scores. edge_rates gives the headline false-edge rate (share of Granger edges that are not real), the missed-edge rate, and a direction disagreement: where both graphs have one arrow between a pair, how often they point opposite ways. score_triad adds F (edge F1 against the true graph), S (agreement with the held-out graph) and M (true edges divided by inferred edges). A positive control scores the true graph against itself and must give F1 = 1.

Differences from the textbook use. The true graph is a 15-frame reachability graph: an edge means byte \(j\) changed by any route, direct or indirect. It is measured at one state, while Granger is fitted on the whole trajectory. Both choices favour Granger, not penalise it. The bytes are also integers that jump in steps, not the smooth, noisy signals the linear model assumes.

Reading the result

The figure sets the Granger graph beside the true data-flow graph over the same candidate bytes (Pong). Here the two hardly overlap: the true graph has whole rows of edges (the score and ball bytes reach many cells within 15 frames), while Granger asserts almost nothing, and what it does assert is not in the truth. In games with many moving bytes (Ms. Pac-Man, Q*bert) the Granger graph turns dense instead, with many bytes appearing to drive many others. Either way most Granger edges have no counterpart in the truth, which is why the false-edge rate sits near its ceiling and the faithfulness is among the lowest in the battery. The subsystem scope in the record tells the same story at coarse scale. Changing the lag or the threshold moves edges around but does not fix the picture, because the shared frame loop creates the predictability.

Pitfalls

  • Precedence is not causation. A common driver seen at different delays produces strong, significant, directed edges between units that never interact (the toy example).
  • Lock-step systems break the test. When everything is updated by one clock, almost every series predicts almost every other one. Deep networks run by a fixed schedule over time steps or layers share the problem.
  • Model mismatch. The test assumes linear, stationary, noisy series. Integer counters that wrap at 256, flags and step jumps violate all three. Stokes & Purdon show that filtering and model order distort results even on well-behaved data.
  • Multiple testing. With \(n\) units there are \(n(n-1)\) tests. At \(\alpha=0.05\) some edges appear by chance alone, before any confounding.
  • The fix is an intervention, not a better statistic. Only cutting or setting a unit separates “earlier” from “cause”. See lesions and activation patching.

How it's scored

The score is the false-edge rate of the Granger-inferred graph against the true data-flow. We let Granger causality infer directed edges from the timing of CPU, TIA, and RIOT activity, then compare each inferred edge to the true wiring the oracle certifies. An inferred edge that is not real is a false edge, and the false-edge rate counts them; faithfulness is one minus that rate. On the VCS the rate is at or near one, because the machine is clock-locked and almost every signal is predictable from almost every other one cycle earlier. So Granger causality infers edges everywhere, and nearly all of them are spurious. Neither a longer lag nor a stricter threshold repairs this, because the shared clock, not a real dependency, creates the predictability. The grading is always against the intervention oracle, which is the only thing that separates precedence from causation here. There is no sprite-position hard-case for this method; its output is a directed graph. The audit box reports the measured faithfulness across the scored games, and it is among the lowest in the battery, which is the point: timing-based causal inference fails on a machine whose timing is shared.

The score is measured against the §1 intervention oracle — never against another interpretability method. F (faithful) is always vs the oracle; see the execution stack. How each of F / S / M is actually computed for this method (and whether it matches the paper) is in the box just below; the numbers are in the In the audit box under it.

content-F and position-F are n/a for this method. The content-vs-position split applies only to pixel-attribution methods — those that produce an attribution map over the framebuffer, whose score can be read separately on the smooth content outputs and the discrete position outputs (where the naive gradient is provably zero). Applied on the substrate

  1. assemble the shared gameplay-state testbed + cause-density gate — build_a6_shared_state(game) -> build_shared_testbed(game; ...) runner
  2. build_shared_testbed definition: booted checkpoint + shared output + gate — function build_shared_testbed(game; ...) runner
  3. cause-density gate counts causes with |Delta_y|>floor via the oracle — cause_density = count(>(floor), deltas) runner
  4. record a (frames x width) RAM tape by stepping the ROM with A6's per-game settings — a6_record_tape(game, frames, actions) runner
  5. step the real emulator one frame per action while recording — env_step!(env, Int(actions[t])) jutari

The computation

  1. cell-level Granger causality (method under test): pairwise VAR-based Granger test over candidate-cell series, edge i->j iff G>=tau and p<=alpha (a directed graph) — run_cell_granger(tape, cands; p, granger_tau, alpha) runner
  2. subsystem-level Granger over pooled RAM-region activity time series — run_subsystem_granger(tape; p, granger_tau, ...) runner

Scored against the exact intervention oracle Δy(u): run_intervention(checkpoint, actions, target_frame, horizon, cause).
