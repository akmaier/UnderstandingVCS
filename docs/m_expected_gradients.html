Expected Gradients

Erion et al. 2021 (NMI)

← back to the method catalogue

What it does?

Expected Gradients removes the single-baseline choice from Integrated Gradients by averaging over many baselines. Instead of one reference, it draws references from a distribution of real states and averages the integrated-gradient attribution across them. This makes the result stable: it no longer depends on one arbitrary baseline, and the attributions are provably consistent across reference draws. The method was introduced to fix the perennial worry that Integrated Gradients can be gamed by picking a convenient baseline. We apply it to the VCS by averaging integrated gradients over a pool of recorded machine states. The result is very stable but not more accurate. Each integrated-gradient term contains the factor input-minus-baseline. When the reference pool holds bytes that are constant across states, that factor is zero and the attribution collapses. Even on a varied gameplay reference pool, and with the sampler restoring a position gradient, the method carries almost no true causal signal, and on a sprite's position it still vanishes for the usual reason. It is the clearest case in the study of a method that is more careful and more expensive, yet buys stability without buying faithfulness. That trade-off is exactly what makes it worth measuring here.

The idea in plain words

Integrated Gradients (IG) needs a baseline, an input that means “nothing”. As the IG guide showed, the answer depends heavily on that choice: a black image, a blurred image and random noise each give a different map. There is rarely a single right “nothing”.

Expected Gradients (EG) sidesteps the choice. Instead of one hand-picked baseline it uses a whole reference distribution: a pool of real inputs, for example images from the training set. It runs IG from many randomly drawn references and averages the results. The attribution then answers “how does this input differ from a typical input, and which features carry the difference?” This links EG to Shapley values from game theory, which also average a feature's contribution over many reference situations. EG is stable and keeps completeness in expectation. But stable does not mean faithful, and averaging differences can cancel them.

How it works on a neural network

With \(y = f(x)\) and a reference distribution \(D\), EG assigns input \(i\) the expected value (average) of the IG integrand over references \(x'\) and path positions \(\alpha\):

\[ \mathrm{EG}_i(x) \;=\; \mathbb{E}_{x' \sim D,\;\alpha \sim U(0,1)} \Big[(x_i - x'_i)\,\frac{\partial f}{\partial x_i}\big(x' + \alpha(x - x')\big)\Big]. \]

Erion et al. estimate it by Monte Carlo integration: draw \(M\) pairs \((x'^{(m)}, \alpha_m)\), one gradient each, and average. There is no inner Riemann sum; the random \(\alpha\) does the path integral. Summing over \(i\) gives completeness in expectation: \(\sum_i \mathrm{EG}_i = f(x) - \mathbb{E}_{x'}[f(x')]\).

Toy example: averaging over baselines. \(f(x_1, x_2) = x_1 x_2\) at \(x = (2, 3)\), with \(D = \{(0,0),\,(2,0)\}\), each drawn half the time. From the IG guide: IG from \((0,0)\) is \((3, 3)\); IG from \((2,0)\) is \((0, 6)\). EG is the average, \((1.5,\ 4.5)\). Check: \(1.5 + 4.5 = 6 = f(x) - \tfrac12\big(f(0,0) + f(2,0)\big) = 6 - 0\). The baseline choice is no longer a single arbitrary pick, but the result now depends on the pool \(D\).

Toy example: cancellation. Let \(f(x) = x\) at \(x = 3\), with references \(\{1, 5\}\). The two IG terms are \(3 - 1 = 2\) and \(3 - 5 = -2\). EG \(= 0\). Yet \(f\) depends on \(x\) one-for-one. EG measures how far \(x\) is from the average reference. An input sitting at the typical value gets no credit, however much the output depends on it.

Recipe

  1. Build a reference pool \(D\) of real inputs (on a network: training examples).
  2. Draw \(M\) references \(x'^{(m)}\) from \(D\) (with replacement) and one \(\alpha_m \sim U(0,1)\) for each.
  3. For each pair, form \(x' + \alpha (x - x')\), run one backward pass, and multiply the gradient by \((x - x')\).
  4. Average the \(M\) products: that is the EG attribution.
  5. Optionally check completeness against \(f(x) - \overline{f(x')}\), and repeat with other seeds to measure stability.

How we apply it to the VCS

The runner implements Erion's single-\(\alpha\)-per-reference estimator over the RAM vector: 64 draws per run, each a uniformly sampled row of \(D\) and a uniform \(\alpha\). It repeats this with five seeds, reports the mean pairwise cosine similarity between the seeds' maps (stability), and also scores single-baseline IG with the zeros baseline on the same output for a head-to-head comparison.

  • The reference pool. \(D\) is built by replaying the shared seeded gameplay stream and recording the RAM after each of the first 90 frames. An earlier version used a pool from a NOOP (no-input) replay. There, many candidate bytes never changed, so \(x - x' = 0\) for every reference and EG was exactly zero. The gameplay pool was introduced so the causal bytes actually vary across references.
  • Interpolated RAM. As in IG, the blended states \(x' + \alpha(x - x')\) have fractional bytes. They are only fed to the differentiable read, never executed on the machine.
  • Content output. The one-hot read has gradient \(e_s\) everywhere, so \(\mathrm{EG}_s = \frac1M\sum_m (x_s - x'^{(m)}_s)\): the current byte minus the average of the sampled references, and 0 for every other byte. This is the cancellation toy for real. A score byte that only grows keeps a clear signal. A byte that sits near its own trajectory average gets almost none, though the oracle may show it matters. The runner records the byte's value, its range over \(D\), and whether EG vanished across all seeds.
  • Position output. The naive gradient is zero for every reference. With the sampler, each draw contributes \((x - x')\) times the kernel's slope at one random point of its path, a noisy one-sample estimate of the occupancy difference between the sprite at the reference's column and at the real one.
  • Scoring is the shared contract: correlation and precision@3 against the oracle, deletion/insertion curves on the real ROM, and an oracle-vs-itself control.

Reading the result

The stability score is high: different seeds give nearly the same map. That is EG's promise, and it keeps it. But look at agreement with the oracle. On the content output the map is still a single spike at the read byte, now sized by its distance from the average reference, and that spike can shrink to almost nothing. On the position output agreement stays low. Overall EG is among the least faithful attribution methods in the study while producing tidy, plausible-looking maps. That combination, high plausibility and low faithfulness, is exactly what the intervention oracle is designed to expose.

Pitfalls

  • Stable is not faithful. Averaging removes randomness from the baseline choice, not error. A map can be perfectly reproducible and wrong.
  • Cancellation. Signed differences from references above and below the input cancel. Inputs at their typical value get little credit even when the output depends on them.
  • The pool is the new baseline. Results depend on \(D\). A pool where an input never varies gives it zero credit, as the NOOP pool did on the VCS.
  • Monte Carlo noise. One gradient per draw is cheap but noisy; check stability across seeds, as the runner does.
  • Still a gradient method. Where the gradient vanishes (sprite timing), no reference distribution can bring it back.

How it's scored

The score is the Pearson correlation of the Expected-Gradients attribution with the oracle's exact causal map, reported raw, and the grading is always against the intervention oracle. Expected Gradients averages Integrated Gradients over a distribution of baselines, which makes the attribution provably stable across reference draws, but stability is not accuracy. Each term carries the factor input-minus-baseline, so when the reference pool holds bytes that are constant across states, that factor is zero and the attribution collapses. Even on the redesigned gameplay reference pool, and with the differentiable sampler turned on for the position regime, the method carries almost no true causal signal, and it is the lowest-faithfulness attribution method in the study. On a sprite's position it still vanishes for the usual reason: the naive gradient is zero on a discrete strobe-timed step and averaging baselines does not change that. Its plausibility proxy is high, which places it squarely in the danger zone of high plausibility with low faithfulness. The audit box reports the measured all-regime faithfulness across the 42 scored games, so the low number is an average over the whole scored set, not one unlucky game.

The score is measured against the §1 intervention oracle — never against another interpretability method. F (faithful) is always vs the oracle; see the execution stack. How each of F / S / M is actually computed for this method (and whether it matches the paper) is in the box just below; the numbers are in the In the audit box under it.
