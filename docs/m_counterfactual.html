On-distribution counterfactual

cf. Olson 2021; Atrey 2020

← back to the method catalogue

What it does?

An on-distribution counterfactual asks the smallest realistic change that flips the output. Instead of occluding with an artificial value, it edits the input toward a genuine alternative the system could actually produce, and finds the smallest such edit that changes the output. The explanation is the edit itself: 'change these cells to these plausible values and the outcome changes'. The point of the on-distribution constraint is to answer the objection that occlusion and clamping can set an input to a value the running system would never create, making the explanation off-manifold. We apply it to the VCS by substituting candidate cells toward a real alternative state, the RAM of another frame of the same ROM, and re-running the bit-exact program. Because the substituted values are ones the machine genuinely produced, the edit stays on the data manifold by construction, and because we re-render the whole machine it is a valid intervention. We compare the minimal edit to the oracle's minimal cause set. The method works on a sprite's position where gradients fail. Its faithfulness here is limited: on some frames no on-distribution content byte varies between frames, so the search finds nothing and the map is flat, and even when it does edit, the single-edit search only partly recovers the true minimal set.

The idea in plain words

A bank’s model rejects your loan. A heat-map of “important features” does not help you much. What helps is a sentence like: “If your income had been 4 000 higher, the loan would have been approved.” That sentence is a counterfactual explanation. It names the smallest change to the input that flips the output. The word comes from logic: a counterfactual is a “what if things had been different” statement. Wachter et al. made it popular in machine learning because it needs no access to the model’s insides and is easy for a person to act on.

There is a trap. The smallest change in raw numbers can produce an input that could never occur: an image with a few strange pixels, a person aged 12 with a mortgage. Such an input is off-distribution (or off-manifold): it lies outside the region where real data lives. An explanation built on it describes the model’s behaviour on nonsense. A good counterfactual is therefore also plausible: the changed input should look like something the world really produces. On the VCS we get plausibility for free, by copying values from other frames the game really visited, and validity for free, by re-running the real program.

How it works on a neural network

For a model \(f\), an input \(x\) and a desired different output, Wachter et al. solve

\[ x^{\ast} \;=\; \arg\min_{x'} \; \lambda\,\big(f(x') - y_{\text{target}}\big)^2 \;+\; d(x, x'), \]

where \(d\) is a distance (often the \(L_1\) norm, which favours changing few features). The explanation is the difference \(x^\ast - x\). Later work adds a plausibility term that keeps \(x'\) near real data, for example a generative model (Olson et al. use one to create counterfactual Atari frames for RL agents). Two properties are checked: validity (does \(f(x^\ast)\) really reach the target?) and sparsity / minimality (how few features were changed?).

Toy example. A loan model approves when \(f(x) = 2\,\text{income} + \text{savings} - 3\,\text{debt} \ge 10\). Applicant: income 3, savings 2, debt 1, so \(f = 6 + 2 - 3 = 5\): rejected. Real applicants in the data have one of these alternative profiles: (income 5, savings 2, debt 1) or (income 3, savings 4, debt 0). Try copying one feature at a time from the first real profile: income 3→5 gives \(f = 9\), still rejected. Copying two features from the second profile, savings 2→4 and debt 1→0, gives \(f = 6 + 4 - 0 = 10\): approved. So the plausible counterfactual is “two more savings and no debt”. A purely numerical optimiser might instead suggest income 3→5.5, a value no applicant has. Both are valid; only one is grounded in real data.

Recipe

  1. Fix the input \(x\), the output \(y = f(x)\), and what counts as a flip (a class change, or a move larger than a threshold).
  2. Collect real alternative inputs \(x'\) from the data, so every substituted value is plausible.
  3. Greedily build a feature set \(S\): at each step copy the feature from \(x'\) that moves \(y\) furthest, until the move is large enough.
  4. Prune: drop any feature from \(S\) whose removal keeps the counterfactual valid.
  5. Report \(S\) and the new values as the explanation, and check validity and minimality.

How we apply it to the VCS

The runner uses the shared gameplay testbed: seeded random actions, a checkpoint at \(f^*\), a 15-frame horizon. Every number below comes from a real re-run of the emulator.

  1. Alternative pool. The runner replays the same action stream to several earlier frames and keeps their full RAM. These are states the game truly reached, so any byte copied from them is an on-distribution value. This answers the off-manifold objection Atrey et al. raised against saliency explanations for Atari agents.
  2. Content byte. The content output is a candidate byte that both reacts to the oracle’s interventions and actually takes different values across the pool. If no such byte exists, the run falls back to the most causally active byte and records that it does not vary.
  3. Choosing \(x'\). For each output, the runner copies all candidate bytes from each pool frame, re-runs, and picks the frame that moves \(y\) the most: the most different real world.
  4. Per-cell map. Copy one byte at a time from \(x'\) and re-run. The size of the change in \(y\) is that byte’s attribution, which is scored against the oracle like every other attribution method (correlation, precision@3, deletion/insertion curves).
  5. Minimal valid edit. Greedy forward selection adds the byte that moves \(y\) furthest until the move reaches \(\tau\) of the full move; a backward pass removes redundant bytes. The runner reports validity and minimality: \(|S|\) divided by the number of bytes that move \(y\) on their own.

Because the method intervenes rather than differentiates, it works on the position output, where the gradient methods see an exact zero. The difference from Wachter et al. is that we never optimise continuous values. We only substitute whole bytes from real frames. That keeps every edit plausible per byte, but a combination of bytes from another frame inside the current state is not guaranteed to be a reachable state.

Reading the result

The bars show the per-byte counterfactual effect next to the oracle’s true effect. Expect moderate agreement, stronger on content than on position. The two do not test the same edit: the oracle uses fixed pokes (base+17, zero), while the counterfactual copies a value from a real frame. When a byte has the same value in \(x'\) as in \(x\), the counterfactual cannot see it, however important it is. On some states no candidate byte varies, the map is flat, and the run marks the counterfactual invalid rather than inventing one. When an edit is found, it is usually small: one or two bytes suffice.

Pitfalls

  • Off-manifold edits. Unconstrained optimisation finds inputs no real system produces (Laugel et al.). Copying values from real frames avoids that per feature, but a mix of features from different frames can still be unreachable.
  • The answer depends on the alternative. A counterfactual only reveals features that differ between \(x\) and \(x'\). A different reference frame gives a different explanation.
  • Many valid counterfactuals. Usually several small edits flip the output. Greedy search returns one of them, not necessarily the smallest, and it can miss sets whose bytes only matter together.
  • Valid is not causal in the world. In a neural net a valid counterfactual describes the model, not reality. On the VCS model and reality coincide, which is exactly why we can check it.

How it's scored

The score is the Pearson correlation of the minimal counterfactual edit with the oracle's exact causal map, together with the edit's minimality against the oracle's minimal cause set, and the grading is always against the intervention oracle. The method substitutes candidate cells toward a real alternative state, another frame of the same ROM, and re-runs the bit-exact program, so the edit is on-distribution and a valid intervention, and it works on a sprite's position where the gradient family scores zero. That is why there is no position collapse here in principle. Its faithfulness is nonetheless only moderate. On some frames no on-distribution content byte varies between frames, so the search finds no valid edit and the map is flat; we mark those cells invalid rather than score them as important. Even when a valid edit exists, the single-edit search only partly recovers the true minimal set, so the correlation stays modest. Minimality is central here, because the method explicitly seeks the smallest flipping edit. The grading is always against the oracle. The audit box reports the measured all-regime faithfulness across the 44 scored games, so the moderate number reflects both the no-op frames and the partial recovery on the frames where the search does run.

The score is measured against the §1 intervention oracle — never against another interpretability method. F (faithful) is always vs the oracle; see the execution stack. How each of F / S / M is actually computed for this method (and whether it matches the paper) is in the box just below; the numbers are in the In the audit box under it.
