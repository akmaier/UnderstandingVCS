LIME

Ribeiro et al. 2016

← back to the method catalogue

What it does?

LIME explains one prediction by fitting a simple model nearby. Around the input of interest it generates many perturbed versions, records the output for each, and then fits a sparse linear surrogate to that local data. The weights of the surrogate are read as the explanation: which inputs, locally, push the output up or down. The idea is that even a complicated system is roughly linear in a small neighbourhood, so a linear fit there is both faithful and easy to read. LIME is model-agnostic and one of the most cited attribution methods. We apply it to the VCS by perturbing the candidate causes around the live state, re-running the program to get outputs, and fitting a local linear model whose weights we correlate with the true causal map. Because the perturbations are real re-runs, LIME works on a sprite's position where gradients fail. It fits both content and position structure reasonably well, so it lands among the more faithful attribution methods. Its main caveats are the usual ones: the explanation depends on how the neighbourhood is sampled and on the surrogate's fit quality, so it can be unstable across runs. On the VCS we can check its surrogate against the exact answer, which is a test the method never gets on a real network.

The idea in plain words

A deep network is a very curvy function. But zoom in far enough on any smooth curve and it looks like a straight line. LIME uses this idea. To explain one prediction, it builds a simple model (a straight-line, i.e. linear, model) that imitates the network only near this one input. Such a stand-in model is called a surrogate. The weights of the surrogate are the explanation: a large positive weight means “this part pushes the output up, around here”.

How do you get data to fit the surrogate? You make it. Switch random parts of the input off (for an image: grey out random superpixels, patches of similar colour), run the network on each version, and record the outputs. Versions that are close to the original get a high weight in the fit, far-away versions a low one. Then fit the line. LIME is model-agnostic: it treats the model as a black box, so it works for networks, random forests, or, as here, a game console.

How it works on a neural network

Describe each perturbed version by a binary vector \(z \in \{0,1\}^d\): \(z_j = 1\) if part \(j\) is present, \(0\) if it was switched off. The original input is \(z = \mathbf 1\) (all present). Sample \(z_1,\dots,z_N\), run the model on each, \(y_k = f(h(z_k))\), where \(h\) maps \(z\) back to a real input. Weight each sample by its closeness to the original, \(\pi_k = \exp(-D(z_k,\mathbf 1)^2/\sigma^2)\), with distance \(D\) and kernel width \(\sigma\). Then solve the weighted least-squares problem

\[ (w, b) \;=\; \arg\min_{w,b}\; \sum_{k=1}^{N} \pi_k\,\big(y_k - w\cdot z_k - b\big)^2 . \]

The coefficients \(w_j\) are the attribution. The library version also keeps only the top few features (a sparse fit) and adds a small ridge penalty. The fit's \(R^2\) (the share of the output variation the line explains) tells you how linear the neighbourhood really is.

Toy example. Two parts, \(f(z) = 3z_1 + 2z_1z_2\). The four possible samples are \(f(1,1)=5\), \(f(1,0)=3\), \(f(0,1)=0\), \(f(0,0)=0\). Give the original weight 1, the two one-off samples weight 0.5, the all-off sample 0.25. Solving the \(3\times3\) normal equations gives \(w_1 = 13/3 \approx 4.33\), \(w_2 = 4/3 \approx 1.33\), \(b = -8/9\). Compare with the truth at the original: switching off \(z_1\) costs 5, switching off \(z_2\) costs 2. With equal weights the fit would give \(w_1 = 4\), \(w_2 = 1\), \(b = -0.5\). The locality weights pull the line toward the original, so \(w_2\) moves from 1 toward the local value 2. No line can fit the interaction term \(2z_1z_2\) exactly; the surrogate spreads it over both coefficients, and \(R^2 < 1\) shows it.

Recipe

  1. Choose the output \(y\), the interpretable parts, a number of samples \(N\), a keep-probability and a kernel width \(\sigma\).
  2. Draw \(N\) random present/absent vectors \(z_k\) (include the original \(z=\mathbf 1\)).
  3. Turn each \(z_k\) into a real input (absent parts set to the baseline), run the model, record \(y_k\).
  4. Weight each sample by its closeness to the original, \(\pi_k = \exp(-D(z_k,\mathbf 1)^2/\sigma^2)\).
  5. Fit \(y \approx w\cdot z + b\) by weighted least squares; report \(w\) and the fit's \(R^2\).
  6. Repeat with other random seeds to see how stable \(w\) is.

How we apply it to the VCS

Sampling. lime_sample draws \(N = 300\) present/absent vectors over the candidate RAM cells. Row 1 is forced to the original (all present); every other cell is present with probability 0.5. For each row, masked_read_y copies the checkpoint, zeroes the absent cells with intervene_ram!, plays the recorded 15 actions with env_step!, and reads \(y\). These 300 real-emulator runs are the whole cost of one fit.

Weights. lime_weights uses the cosine distance between \(z\) and \(\mathbf 1\) and the kernel \(\exp(-D^2/\sigma^2)\) with the LIME library's default width \(\sigma = 0.75\sqrt{d}\) (\(d\) = number of cells). Cosine distance here lies between 0 and 1, while \(\sigma\) is above 2 for 8 or more cells, so all weights stay between roughly 0.8 and 1. In practice the fit is close to an unweighted least-squares fit over a broad neighbourhood (about half the cells zeroed per sample), not a tight local one.

Fit. fit_weighted_linear solves the ridge-regularised normal equations and returns the coefficients, the intercept and the weighted \(R^2\). Each RAM cause gets \(|w_j|\) of its cell; TIA and joystick causes get 0. The sign is dropped because the oracle column is a magnitude.

Stability. LIME depends on its random samples, so the runner refits from 5 independent seeds (5 × 300 re-runs per output) and records the spread of the oracle correlation, of \(R^2\), and the average cosine similarity between the coefficient vectors.

How is this different from the oracle? The oracle asks one exact question per cause: “change only this, at the real state, what happens?” LIME asks many joint questions (half the cells zeroed at once) and then compresses the answers into one line. If the game logic were additive, the line's coefficients would equal the zeroing effects. Where it is not (thresholds, AND-like interactions, sprite timing), the line averages the effect over damaged contexts, and the \(R^2\) tells you how much it missed.

Reading the result

Bars are \(|w_j|\) per cause next to the oracle's true effect; TIA and joystick causes are zero for LIME by construction, and both causes of a byte share a height. Read the record's surrogate \(R^2\) before trusting the bars: a low value is LIME admitting that a line is a poor model of the game near this state. Also read the stability block: if refits with other seeds disagree, the ranking is partly sampling luck. Expect LIME to track the main structure on both content and position outputs reasonably well.

Pitfalls

  • The neighbourhood is a choice. Kernel width, keep-probability and the “off” value all change the answer. With our defaults the weights barely vary, so “local” really means “about half the cells zeroed”.
  • Interactions get smeared. A linear surrogate cannot represent AND-like effects; it splits them across coefficients (toy example). Check \(R^2\).
  • Instability. Different random samples give different coefficients (Alvarez-Melis & Jaakkola). That is why we refit with several seeds and report the spread.
  • Explanations can be gamed. Slack et al. built models that detect LIME's off-distribution samples and behave differently on them. The VCS cannot do that, but it does run the program on states the game would never reach.

How it's scored

The score is the Pearson correlation of the local linear surrogate's weights with the oracle's exact causal map, reported raw, and the grading is always against the intervention oracle. LIME fits a sparse linear model to real re-runs of the machine around the live state, so its perturbations are valid interventions and it works on a sprite's position where the gradient family scores zero. That is why there is no position collapse here. It fits both content and position structure reasonably well, so it lands among the more faithful attribution methods. The surrogate also reports its own fit quality, the local R-squared, which acts as an internal check on how linear the neighbourhood really is. The main caveats the score reflects are the usual ones for LIME: the explanation depends on how the neighbourhood is sampled and on the surrogate's fit, so it can vary across runs, and we report that stability alongside the correlation. The grading never compares LIME to another method, only to the oracle. The audit box reports the measured all-regime faithfulness across the 44 scored games, so the number reflects the whole scored set. On the VCS we can test the surrogate against the exact answer, which a real network never allows.

The score is measured against the §1 intervention oracle — never against another interpretability method. F (faithful) is always vs the oracle; see the execution stack. How each of F / S / M is actually computed for this method (and whether it matches the paper) is in the box just below; the numbers are in the In the audit box under it.
