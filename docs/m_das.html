Interchange interventions / DAS

Geiger et al. 2021, 2023

← back to the method catalogue

What it does?

Distributed Alignment Search, or DAS, looks for a high-level concept inside the low-level state. It learns a rotation of the internal representation so that a chosen direction, or subspace, lines up with a supplied causal variable. It then tests the alignment by an interchange intervention: swap that subspace between two runs and check whether the output changes exactly as the concept would predict. The method is a leading tool for arguing that a network represents an abstract variable in a specific, possibly distributed, part of its activations. We apply it to the VCS by aligning a learned subspace of the state to a known game variable and measuring interchange accuracy against the true variable. On this transparent machine the alignment is exact: swapping the aligned subspace reproduces the concept's effect perfectly, while a mis-aligned control does not. There is an important caveat that the VCS makes explicit. The concept DAS aligns to is one we supplied from an external label, not one the method discovered. So a perfect interchange accuracy confirms an alignment to a given meaning; it does not show the method found the meaning on its own. DAS is thus a strong test of whether a supplied concept is causally real in the state, and a clean example of the difference between verifying a label and discovering one.

The idea in plain words

Suppose you believe a network solves a task with a simple algorithm. For example, to compare two numbers it first computes “which one is bigger” and then reports it. That simple algorithm is a high-level causal model: a few named variables and the arrows between them. The question is whether the network really contains a variable that plays the role of “which one is bigger”. Causal abstraction answers it with an interchange intervention: take the hidden state that should hold the variable from a source input, put it into the run on a base input, and check whether the output changes exactly as the high-level model predicts when you swap that variable.

The catch is that a network rarely stores a variable in one neuron. It may be spread across many neurons, along some direction of the activation space. That is a distributed representation. Distributed Alignment Search (DAS) therefore learns a rotation of the activation space. After rotating, the first few coordinates should hold the variable, and swapping only those coordinates should behave like swapping the variable. On the VCS we already know where every variable lives, so the method turns into a clean test of the swap logic itself, and a lesson about what a perfect score can and cannot prove.

How it works on a neural network

Let \(h(x) \in \mathbb{R}^d\) be the hidden vector at some layer for input \(x\). DAS learns an orthogonal matrix \(R\) (a rotation: \(R^\top R = I\), so no information is lost) and fixes a number \(k\) of coordinates. The interchange intervention on base \(b\) with source \(s\) is

\[ \hat h \;=\; R^\top\!\Big( (I - P_k)\,R\,h(b) \;+\; P_k\,R\,h(s) \Big), \]

where \(P_k\) keeps only the first \(k\) rotated coordinates. The rest of the network then runs on \(\hat h\). The high-level model predicts an output \(y^\ast(b, s)\): the answer you would get on \(b\) if its variable took \(s\)’s value. \(R\) is trained by gradient descent so the network’s output matches \(y^\ast\) on many \((b, s)\) pairs. The score is interchange intervention accuracy (IIA): the fraction of held-out pairs where the swapped run gives \(y^\ast\).

Toy example. Let \(h = (h_1, h_2)\) with \(h_1 = u + v\) and \(h_2 = u - v\), where the variable we care about is \(u\). No single neuron is \(u\). But rotate by 45°: \(R h = \tfrac{1}{\sqrt 2}(h_1 + h_2,\; h_1 - h_2) = \sqrt 2\,(u, v)\). Now the first rotated coordinate is exactly \(u\) (times a constant). Base \(u{=}1, v{=}3\); source \(u{=}5, v{=}0\). Swap coordinate 1: the patched state encodes \(u{=}5, v{=}3\), so \(h = (8, 2)\). That is precisely the prediction “base with source’s \(u\)”. Swapping neuron \(h_1\) alone would give \(h = (5, -2)\), which decodes to \(u{=}1.5, v{=}3.5\): the wrong \(u\) and a corrupted \(v\). This is why DAS looks for a direction, not a neuron.

Recipe

  1. Write down the high-level causal model and choose the variable \(V\) you want to locate.
  2. Choose a layer and a subspace size \(k\); initialise a rotation \(R\).
  3. Sample base/source pairs; compute the high-level prediction \(y^\ast(b,s)\) for swapping \(V\).
  4. Run the interchange intervention in the rotated basis and train \(R\) so the network output matches \(y^\ast\).
  5. Report IIA on held-out pairs, and compare it with a control (a random or wrong subspace).

How we apply it to the VCS

The runner reads its variables from the game’s candidate file: each candidate RAM byte becomes a variable whose value is the byte itself, plus a background-colour variable read from a screen pixel. The claim being tested is that “variable \(V\) lives in byte \(i\)”. Everything runs on the shared gameplay checkpoint at \(f^*\), with a 15-frame tail.

  1. Interchange-effect matrix. For every cell \(i\), write the directed source value base+17 into a copy of the base checkpoint, run 15 frames, and read every variable \(j\). The same swap is replayed from a fresh boot; the two matrices must be identical.
  2. IIA of the true alignment. For each RAM variable, swap its own cell and read the cell back at the swap frame. It must hold the source value. This is done for the directed source and, where the natural RIGHT-press source really differs from base, for that too.
  3. Misaligned control. Swap the next candidate cell in the list and read variable \(V\). It matches the prediction only if the two cells happen to alias, so accuracy should drop to near zero. This is what makes a perfect aligned score meaningful.
  4. Alignment search. For each variable, the runner picks the cell whose swap best reproduces the variable’s own 15-frame effect, and checks whether that is the true cell. Cells the program overwrites within the horizon (transient cells) give no signal and are listed separately.

Be clear about the difference from real DAS. There is no learned rotation and no gradient training. The search space is the set of single bytes, because on the VCS the program’s variables are stored one per byte. The concept labels come from the candidate file, not from the method. So the VCS run checks that interchange logic and the IIA metric reward the right alignment and punish a wrong one; it does not show that DAS would discover the variable unaided.

Reading the result

Expect the aligned IIA at the ceiling and the misaligned control near the floor. The gap between the two is the real content: it shows the metric discriminates. Then look at the alignment search and the transient list. Variables whose cell is rewritten every frame cannot be aligned by their downstream effect, because there is none within the horizon. A perfect score here verifies a given label; it is not evidence that the method found the label itself.

Pitfalls

  • A supplied variable is not a discovered one. DAS tests an alignment you propose. If you choose the hypothesis from the same labels you score against, a perfect IIA is guaranteed in advance.
  • Interpretability illusions. Makelov et al. show that a learned subspace can reach high IIA by activating a dormant pathway the model never uses on real inputs. Always compare against a control and check the subspace on natural data.
  • Too much freedom. A large subspace or a very expressive map can make almost any hypothesis “fit”. Keep \(k\) small and report held-out accuracy.
  • Readout timing. On the VCS, reading the variable right at the swap is trivially exact. Reading after 15 frames shows that many cells are overwritten by the program, so present is not the same as used.

How it's scored

The score is the interchange accuracy of the aligned subspace against the true variable. We align a learned subspace of the state to a supplied concept, then swap that subspace between two runs and check whether the output changes exactly as the concept predicts; the fraction of correct interchanges is the accuracy. The grading is against the intervention oracle, and on this transparent machine the alignment is exact, so interchange accuracy is at the ceiling, while a mis-aligned control scores zero. Faithfulness for this method is that interchange accuracy. There is no sprite-position hard-case here, because DAS operates by intervention rather than by a gradient. The essential caveat the audit makes explicit is that the concept DAS aligns to is one we supplied from an external label, not one the method discovered. So a perfect interchange accuracy is guaranteed in advance: it confirms an alignment to a given meaning, and does not show the method found the meaning on its own. The grading is always against the oracle, never against another method. The audit box reports the measured triad. DAS is thus a clean example of the difference between verifying a supplied concept and discovering one, which only a machine with known ground truth can separate.

The score is measured against the §1 intervention oracle — never against another interpretability method. F (faithful) is always vs the oracle; see the execution stack. How each of F / S / M is actually computed for this method (and whether it matches the paper) is in the box just below; the numbers are in the In the audit box under it.
