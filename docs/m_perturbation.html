Extremal / meaningful perturbation

Fong & Vedaldi 2017; Fong et al. 2019

← back to the method catalogue

What it does?

Extremal, or meaningful, perturbation learns the smallest mask that most changes the output. Rather than sliding a fixed occluder, it optimises a soft mask over the inputs, searching for the smallest region whose removal most disrupts the output, subject to a bound on the mask's area. The learned mask is read as the explanation: the compact set of inputs the output really depends on. For images this yields a tight, optimised heat-map instead of a brute-force sweep. The method was designed to answer a specific criticism, that hand-placed occluders are arbitrary and can push the input off the data manifold. By optimising a bounded, smooth mask of real occlusion re-runs, it stays closer to valid interventions. We apply it to the VCS by optimising an area-limited mask over the candidate causes, each mask entry a genuine occlude-and-re-run, and comparing the learned mask to the true minimal cause set. Because every step is a real intervention, it works on a sprite's position where gradients fail, and it partly overlaps the true causes. Its faithfulness is moderate: the optimisation finds a compact set that is on the right track but does not exactly match the oracle's minimal set. It is a strong, on-manifold member of the intervention family and a fair test of whether optimising the mask beats simply sliding one.

The idea in plain words

Occlusion slides a fixed grey square and reports a number for every position. That raises two questions. Why a square? Why that size? Extremal perturbation turns the question around. It asks: what is the smallest region I must remove to destroy the prediction? The answer is a mask, a map that says for each input whether it is removed. The mask is found by optimisation, not by sliding.

The mask is the explanation. A good mask is small (it points at few inputs) and extremal (removing those inputs changes the output as much as possible). Fong and Vedaldi called the 2017 version “meaningful perturbation”, because the removal should look like a plausible change (a blur, not a random noise pattern). The 2019 version fixes the mask area in advance, say 10 % of the image, and finds the best mask of exactly that size. This removes a hard-to-tune penalty weight. It is still a black-box method: it only needs to run the model on masked inputs.

How it works on a neural network

Let \(m \in [0,1]^n\) be a soft mask (\(m_i = 1\): input \(i\) removed, \(0\): kept) and \(\Phi(x; m)\) the perturbed input, e.g. \(x\) blended with a blurred copy where \(m\) is high. The 2017 “deletion game” solves

\[ m^\star = \arg\min_{m}\; \lambda\,\|m\|_1 \;+\; f\big(\Phi(x; m)\big) , \]

trading mask size (the \(\ell_1\) regulariser \(\|m\|_1\), weighted by \(\lambda\)) against how low the class score goes. The 2019 “extremal” version replaces the penalty by a hard area constraint \(\|m\|_1 = a\cdot n\). Both are solved by gradient descent on \(m\), with smoothness tricks so the mask does not become a noisy pattern that fools the network (an adversarial mask).

Toy example. \(f(x) = 4x_1x_2 + x_3\) at \(x = (1,1,1,1)\) (\(x_4\) unused), removal sets an input to 0, and the budget is 2 inputs. Removing one input at a time changes \(f\) by 4, 4, 1, 0. A greedy search takes \(x_1\) first (change 4). Next it tries each remaining input together with \(x_1\): adding \(x_2\) still gives 4 (the product is already dead), adding \(x_3\) gives 5. So the mask is \(\{x_1, x_3\}\), which destroys the whole output with two inputs. Note what happened to \(x_2\): it is just as important as \(x_1\), but once \(x_1\) is removed it adds nothing, so it is not in the mask. A minimal mask names a sufficient set, not all important inputs.

Recipe

  1. Choose the output \(y\), a removal operator (blur, grey, zero) and an area budget \(a\) (fraction of inputs that may be removed).
  2. Start from an empty mask; record the intact output \(y(x)\).
  3. Search for the mask of at most \(\lceil a\cdot n\rceil\) inputs that maximises \(|y(x) - y(\text{masked } x)|\): gradient descent on a soft mask for a network, greedy forward selection on a black box.
  4. Stop when the budget is used up, or when adding one more input no longer increases the change.
  5. Report the mask (the selected set), and score it against the true causal set with intersection-over-union (IoU).

How we apply it to the VCS

Why greedy, not gradients. The original optimises a soft mask by gradient descent. On the VCS that would fail for the same reason saliency fails on the position output: the machine is a discrete index computer and \(\partial y/\partial m = 0\) almost everywhere. So the runner optimises the mask directly on the real emulator with greedy forward selection, the discrete, budget-bounded cousin of the original optimiser.

  1. Single-cause pass. For every cause \(i\), masked_abs_dy removes just that cause and re-runs: \(|y(\text{occlude}\{i\}) - y(\text{intact})|\). This pass is literally occlusion.
  2. Greedy growth. Start with \(M = \varnothing\). In each step try every unselected cause \(i\): deepcopy the checkpoint, occlude! all of \(M\cup\{i\}\), run 15 env_step! frames, read \(y\). Add the cause with the largest change.
  3. Stop when \(|M| = \lceil 0.25\,C\rceil\), or when the best addition does not increase the change. If no single removal moves \(y\) at all, the mask stays empty: an honest null.
  4. Per-cause scores. Selected causes get the larger of their entry value and single-cause score, plus a constant lift (the largest single-cause score), so the mask ranks first and its internal order is kept. Unselected causes keep their single-cause occlusion score.

How is this different from the oracle? The oracle probes each cause alone, with two directions (+17 and →0). Extremal perturbation probes sets of causes, and only in the “remove” direction. It can therefore see joint effects the oracle's per-cause map does not contain. But it deliberately reports a minimal set, so a cause that is redundant given the mask (like \(x_2\) in the toy) is left out, even if the oracle ranks it high. For the IoU, causes are reduced to the cell they actually touch, because ram[i]:set and ram[i]:occlude both zero the same byte when masked.

Cost. At most \(\lceil aC\rceil\cdot C\) greedy re-runs plus \(C\) single-cause re-runs and one intact run; every one is a full 15-frame run of the real ROM from the checkpoint.

Reading the result

The figure shows the per-cause scores next to the oracle, and the record lists the selected mask. The selected causes sit on top because of the lift. Check two things. First, are the mask's causes among the oracle's tallest bars? That is what the IoU measures. Second, are there tall oracle bars outside the mask? Usually there are: the mask is a small sufficient set, not the full list of important causes, so expect a partial overlap rather than a perfect match. The method works on the position output too, since it never uses a gradient.

Pitfalls

  • Minimal is not complete. A mask names one small sufficient set. Redundant causes (backups) are left out even when each is important on its own.
  • Greedy is not optimal. Forward selection can be trapped: two causes that only matter together are never picked if neither helps alone. Ties are broken by list order, so the choice between equally good causes is arbitrary.
  • Artefact masks. On images, an unconstrained mask can become an adversarial pattern; the smoothness terms and blur perturbation of Fong et al. exist to stop this. On the VCS every mask is a valid machine state, but zeroing several bytes at once can push the game into states it never reaches in play.
  • The budget shapes the answer. A different area fraction gives a different mask. The 2019 paper reports masks at several areas for this reason; we use one default.

How it's scored

The score is the Pearson correlation of the learned mask with the oracle's exact causal map, together with the mask's overlap, measured as intersection-over-union, against the true minimal cause set. The grading is always against the intervention oracle. Every entry of the mask is a real occlude-and-re-run, so the method is a valid intervention and works even on a sprite's position, where the gradient family scores zero. That is why there is no position-collapse here. Its faithfulness is moderate rather than high: the area-bounded optimisation finds a compact set that partly overlaps the true causes but does not exactly match the oracle's minimal set, so both the correlation and the mask overlap are partial. Minimality is central to this method, because it explicitly seeks the smallest disruptive mask, so the score rewards a mask that is both on-target and small. The grading never compares the mask to another method's mask, only to the oracle's minimal set. The audit box reports the measured all-regime faithfulness across the 42 scored games, so the number reflects the whole scored set rather than the single game where the optimised mask happens to line up best with the true causes.

The score is measured against the §1 intervention oracle — never against another interpretability method. F (faithful) is always vs the oracle; see the execution stack. How each of F / S / M is actually computed for this method (and whether it matches the paper) is in the box just below; the numbers are in the In the audit box under it.

Applied on the substrate

  1. env reset + per-frame step of the bit-exact VCS (masked re-runs step the horizon) — env_reset! / env_step! jutari

  1. value of a masked coalition: occlude every masked cause (do-intervention), step the horizon, read |output delta| vs intact — masked_abs_dy runner
  2. the mask operator = the oracle's occlude! (RAM/TIA -> 0, joystick masked = NOOP) — occlude! -> intervene_ram! / intervene_tia! jutari intervene_ram! jutari_oracle.jl:174, intervene_tia! jutari_oracle.jl:185
  3. extremal-perturbation search: grow the smallest mask that maximally shifts the output, then attribute per cause — extremal_mask runner
  4. snapshot RAM+screen after each masked re-run — snapshot jutari
