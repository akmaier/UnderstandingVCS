# Opcode coverage — 64 conformance ROMs (jutari, hard mode)

Generated by `tools/opcode_coverage.jl`: standard boot (60 NOOP + 4 RESET), then the 3,600-step
`breakout_random_actions` stream; steps 1-60 are the RAM/screen conformance window. Counted per
executed instruction (opcode byte at PC, side-effect-free read). ROMs = `rom_sha256.txt`.

jutari implements 189 opcode bytes: 151 documented, the USBC alias ($EB), and 37 illegal
(27 multi-byte NOPs, 6 LAX, 4 SAX). The other 67 bytes have no handler.

**Boot + conformance window:** 78,849,749 instructions; 134/151 documented opcodes; **0/37 illegal; USBC 0; unimplemented bytes 0**.
**Boot + 3,600 steps:** 1,214,842,126 instructions; 135/151 documented; **0/37 illegal; USBC 0; unimplemented bytes 0**.

Documented opcodes never executed: $01 $0E $21 $2E $3E $41 $5E $61 $6E $7E $81 $DE $E1 $EE $F1 $FE (mostly (zp,X)/(zp),Y forms and abs/abs,X read-modify-write shifts).

Consequence: the 37 illegal opcodes (and USBC) are validated by unit tests only
(`jutari/test/runtests.jl`, `jaxtari/tests/test_p1h_undocumented.py`), not by the 64-game traces.
